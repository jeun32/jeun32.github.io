1편에서 **비지도 학습 개요**와 **토픽 모델링(LDA/NMF)** 을 다뤘습니다.
이번 2편에서는 나머지 절반 — **클러스터 분석(K-means, HDBSCAN)** 과 **차원 축소(PCA, t-SNE, UMAP)** 를 정리합니다.
"왜 요즘은 HDBSCAN을 쓰는지", "차원의 저주가 왜 문제인지"까지 비유를 곁들여 풀어보겠습니다.

## <span style="color:#FEB99C;">1. 클러스터 분석: 문서를 그룹으로 나누기</span>

1편의 **같은 불만 데이터**, 이번엔 미션이 조금 다릅니다.
"불만들을 **그룹으로 나눠서** 후속 조치 담당을 배정하세요."

토픽 모델링이 "무슨 주제들이 섞여 있나"를 봤다면, 클러스터링은 "비슷한 것끼리 묶기"에 집중합니다.
클러스터링 방법을 고를 때 던지는 질문들:

- 내 데이터는 무엇인가? (단어 카운트? 토픽? 임베딩?)
- 클러스터가 몇 개인가? (개수를 아는가?)
- **거리(distance)** 는 어떻게 잴 것인가? (코사인? 유클리드?)

클러스터링 접근은 크게 세 가지로 나뉩니다.

| 유형 | 원리 | 특징 |
|---|---|---|
| **Centroid 기반** | 중심점에서 원/구를 그림 | 가장 직관적, **구형(spherical)만**, 유클리드 거리 |
| **Hierarchical(계층적)** | 유사한 쌍/이웃으로 트리 구성 | 상향식(agglomerative)·하향식(divisive), 유연함 |
| **Density(밀도) 기반** | 점이 빽빽한 곳을 찾음 | **어떤 모양이든** OK, 노이즈 허용 |

> 클러스터링의 어려움들:
> ① 해석이 어려움(토픽 모델과 달리 레이블 숫자만 나옴) ② **차원의 저주** ③ 계산 비용 ④ 초기화 무작위성 → 불안정 ⑤ 품질 평가가 주관적

### 잠깐, 클러스터링은 왜 "품질 평가"가 유독 어려울까?

위 ⑤번을 조금 더 파봅시다. 지도 학습(분류)은 정답(레이블)이 있어서 "몇 % 맞혔나"로 딱 채점됩니다.
하지만 클러스터링은 **비지도 학습**이라 비교할 정답 자체가 없습니다. 게다가:

- **클러스터 경계가 명확하지 않을 수 있다** — 어디까지가 A 그룹이고 어디부터 B 그룹인지 자연이 알려주지 않습니다.
- **평가 지표가 알고리즘마다 다르다** — K-means엔 실루엣·WCSS가 맞지만, HDBSCAN엔 이 지표들이 잘 안 맞습니다(뒤에서 설명).

그래서 클러스터링 평가는 "정답률"이 아니라 **여러 내부 지표(레이블 없이 계산 가능한 지표)를 종합해 사람이 판단**하는, 다소 주관적인 작업이 됩니다.

### 클러스터링 ↔ 토픽 모델링, 왜 함께 쓰나?

1편의 토픽 모델링과 2편의 클러스터링은 사실 **팀을 이룰 수 있습니다.**
토픽 모델링(LDA 등)이 각 문서를 **토픽 분포 벡터**로 바꿔주기 때문입니다.

```text
문서 1: [토픽A 70%, 토픽B 20%, 토픽C 10%]  →  [0.7, 0.2, 0.1]
문서 2: [토픽A 10%, 토픽B 85%, 토픽C  5%]  →  [0.1, 0.85, 0.05]
문서 3: [토픽A 65%, 토픽B 25%, 토픽C 10%]  →  [0.65, 0.25, 0.1]
```

즉 텍스트라는 복잡한 데이터가 **몇 개의 숫자로 요약(차원 축소)** 됩니다.
이렇게 나온 벡터를 클러스터링에 넣으면, 비슷한 분포를 가진 문서끼리 자동으로 묶입니다.

```text
[원본 문서]
    │ ① 토픽 모델링(LDA) → 토픽 분포 벡터 (텍스트를 숫자로 압축)
    ▼
[토픽 분포 벡터]
    │ ② 클러스터링(K-means 등) → 비슷한 분포끼리 그룹화
    ▼
[문서 그룹]   ← 문서 1·3은 토픽A 위주로 같은 그룹, 문서 2는 다른 그룹
```

핵심은 **"대체"가 아니라 "보완"** 이라는 점입니다. 토픽 모델은 "이 문서가 무엇에 관한가(소프트한 주제 비율)"를 주고,
클러스터링은 그 위에서 "그래서 어떤 문서들이 한 부류인가(하드한 그룹)"를 **한 단계 더** 정리해 줍니다.

| 구분 | 토픽 모델링 | 클러스터링 |
|---|---|---|
| 하는 일 | 문서 안의 주제 비율 추출 | 비슷한 문서를 그룹으로 묶음 |
| 결과 성격 | 소프트(한 문서가 여러 토픽에 걸침) | 하드(각 문서가 한 군집에 속함) |
| 관점 | "이 문서는 무엇에 관한가?" | "어떤 문서들이 서로 비슷한가?" |

## <span style="color:#FEB99C;">2. K-means & HDBSCAN</span>

### K-means: 중심에서부터 원을 그린다

가장 원조격인 클러스터링입니다. 절차는 단순합니다.

1. 클러스터 개수 $K$ 를 정하고, $K$ 개의 중심점을 **무작위로** 찍는다
2. 각 점을 **가장 가까운 중심**에 배정한다 (유클리드 거리)
3. 배정된 점들의 중심으로 **중심점을 다시 계산**한다
4. 중심이 거의 안 움직일 때까지 2~3을 반복한다

> 중심점에서 거리로 배정하다 보니 **클러스터 모양이 항상 구형**이 됩니다.
> 또한 유클리드 거리를 쓰므로 **데이터 표준화(standardization)** 가 필수입니다.

- 👍 직관적, 빠름(특히 mini-batch 버전)
- 👎 **구형만** 잡음, 불안정(초기값 의존), 지역 최솟값(local minimum)에 빠질 위험

여기서 "지역 최솟값에 빠진다"는 표현을 짚고 넘어갑시다.
K-means는 처음 중심점을 **무작위**로 찍기 때문에, 어디서 시작하느냐에 따라 도착지가 달라집니다.
손실 함수에 봉우리와 골짜기가 많으면, 진짜 최저점(전역 최솟값)이 아닌 **근처의 얕은 골짜기(지역 최솟값)** 에 갇혀 멈출 수 있습니다.

```text
손실
 │  ╱＼      ╱＼
 │ ╱  ＼   ╱  ＼    ← 여기 얕은 골짜기에 갇히면 (지역 최솟값)
 │╱    ＼_╱    ＼___
 │              ╲___ ← 진짜 최저점(전역 최솟값)을 못 찾음
 └────────────────────
```

그래서 실무에선 초기값을 여러 번 바꿔 돌리거나 `k-means++` 같은 똑똑한 초기화를 씁니다.
특히 **고차원 비정형 데이터**에서는 봉우리·골짜기가 훨씬 많아져 이 문제가 심해집니다.

#### K-means의 평가 지표

K-means의 평가 지표는 풍부합니다.

| 지표 | 방향 | 의미 |
|---|---|---|
| **WCSS/Inertia (Elbow)** | 꺾이는 지점 | 군집 내 제곱합 |
| **Calinski-Harabasz** | 높을수록 좋음 | 군집 간 분산 / 군집 내 분산 |
| **Davies-Bouldin** | 낮을수록 좋음 | 클러스터 분리도 |
| **Silhouette** | +1에 가까울수록 좋음 | 음수면 다른 클러스터에 더 가깝다는 뜻 |

> 참고로 **Accuracy(정확도)** 는 이 표에 없습니다. 정확도는 정답 레이블이 필요한 **지도 학습** 지표라, 레이블이 없는 클러스터링에는 쓸 수 없습니다.

**Elbow(엘보우) 방법** 은 위 표의 WCSS를 이용해 **최적의 클러스터 개수 $K$** 를 찾는 도구입니다.
$K$ 를 늘려가며 WCSS를 그래프로 그리면, 처음엔 급격히 줄다가 어느 지점부터 완만해집니다. 그 **꺾이는 팔꿈치 지점**이 적절한 $K$ 입니다.

```text
WCSS
 │＼
 │  ＼
 │    ＼___  ← 여기가 elbow(꺾이는 지점) → 최적 K
 │        ‾‾‾───___
 └──────────────────── K (군집 수)
    1  2  3  4  5  6
```

#### 실루엣 점수(Silhouette Score) 자세히 보기

평가지표 중 실루엣 점수는, 각 데이터 점이 **자기 군집에 얼마나 잘 맞는지**를 −1 ~ +1 사이로 나타냅니다. 계산은 두 거리의 비교입니다.

- **a** = 자기 군집 안 다른 점들과의 평균 거리 (작을수록 좋음, "우리끼리 잘 뭉쳤나")
- **b** = 가장 가까운 **다른 군집** 점들과의 평균 거리 (클수록 좋음, "옆 그룹과 잘 떨어졌나")

| 점수 | 의미 |
|---|---|
| **+1에 가까움** | 자기 군집에 잘 맞음 (제대로 배정됨) |
| **0에 가까움** | 두 군집 경계에 걸쳐 있음 |
| **−1에 가까움** | `b < a`, 즉 **다른 군집이 자기 군집보다 더 가깝다** → 잘못 배정 |

> ⚠️ 흔한 오해: 실루엣 −1을 "이상치(outlier)"가 아니라,
> **"옆 군집에 더 가까운데 엉뚱한 군집에 배정된 데이터"** 입니다.
> (실루엣 점수의 정의 자체가 "다른 군집과의 거리 비교" 입니다.)

### HDBSCAN: 빽빽하게 모인 곳을 그룹으로

이름이 길지만 뜯어보면 됩니다 — *Hierarchical Density-Based Spatial Clustering of Applications with Noise*.

- **Density 기반** : 중심점이 아니라 **점들의 밀도(빽빽함)** 로 클러스터 정의
- **Hierarchical** : 트리를 만들어 클러스터를 병합/분할
- **Noise** : 모든 점을 억지로 배정하지 않고, 안 맞는 건 **노이즈(-1)** 로 버림

- 👍 **클러스터 개수를 지정할 필요 없음**, 노이즈 허용, 자유로운 모양
- 👎 **고차원에서 약함**(차원의 저주), 레이블 해석 어려움, 품질 평가 어려움

여기서 **Hierarchical(계층 구조)** 이 주는 숨은 장점 하나를 짚고 가겠습니다.
HDBSCAN은 클러스터를 트리로 만들기 때문에, 이 트리를 **어느 높이에서 자르느냐**에 따라
**더 세밀하게(작은 그룹 많이)** 또는 **더 뭉뚱그려서(큰 그룹 적게)** 결과를 조절할 수 있습니다.

```text
        ┌───────────┐
        │  큰 그룹   │   ← 높이 높게 자름 = 덜 세밀 (그룹 적음)
     ┌──┴──┐   ┌───┴──┐
     │ 중  │   │  중  │  ← 중간 높이
   ┌─┴─┐ ┌┴┐ ┌┴┐  ┌─┴─┐
   │세 │ │ │ │ │  │세 │  ← 낮게 자름 = 세밀 (그룹 많음)
```

`min_cluster_size`, `cluster_selection_epsilon`, `cluster_selection_method`(eom/leaf) 같은 파라미터가
이 "세분화 수준(granularity)"을 결정합니다. K-means가 $K$ 하나로 고정되는 것과 달리,
HDBSCAN은 **원하는 해상도로 클러스터를 뽑아낼 수 있다**는 유연함이 있습니다.

#### HDBSCAN이 K-means보다 나은 점 (요약)

| 장점 | 설명 |
|---|---|
| **클러스터 개수 지정 불필요** | K-means의 $K$ 와 달리 자동으로 그룹 수를 찾음 |
| **다양한 밀도·모양 처리** | 구형이 아닌 길쭉하거나 휘어진 그룹도 OK |
| **노이즈 허용** | 안 맞는 점은 −1로 걸러냄 (억지 배정 안 함) |
| **세분화 수준 조절** | 계층 구조라 더/덜 세밀한 클러스터링 선택 가능 |

> "모든 점을 군집에 배정"은 HDBSCAN의 장점이 **아닙니다.** 오히려 노이즈로 버리는 게 HDBSCAN의 특징이자 강점입니다.

## <span style="color:#FEB99C;">3. K-means vs HDBSCAN, 그리고 요즘 실무 방식</span>

두 방법은 철학이 완전히 다릅니다.

| | **K-means** | **HDBSCAN** |
|---|---|---|
| 그룹 개수 | **내가 지정** ("20개") | **자동으로 찾음** |
| 모든 문서 배정? | **무조건 배정** | **노이즈 허용** (-1로 버림) |
| 그룹 모양 | 구형만 | 아무 모양 |

### "요즘은 HDBSCAN이 실무 방식"이라는데, 왜?

여기엔 중요한 오해가 하나 있습니다. 데모에서 **HDBSCAN을 그냥 텍스트에 돌리면 80%가 노이즈**로 나왔습니다.
즉 "HDBSCAN 자체가 K-means를 이겼다"가 **아닙니다.**

진짜 이유는 **입력 데이터가 바뀌었기 때문**입니다.

```text
[옛날] 텍스트 → 단어 세기(DTM/TF-IDF) → 클러스터링
              └ 1000차원, 희소, 단어 뜻 모름

[요즘] 텍스트 → 문장 임베딩(BERT 등) → UMAP → HDBSCAN
              └ 의미를 담은 조밀한 벡터
```

**의미 임베딩의 등장**이 게임체인저였고, 이 임베딩과 궁합이 맞는 게 HDBSCAN이었던 것이죠.
K-means가 임베딩 시대에 불리한 이유:

1. **구형 그룹만 만든다** — 의미 공간의 주제들은 길쭉하거나 휘어져 있음
2. **그룹 개수를 미리 정해야 한다** — 실무에선 주제 개수를 아무도 모름
3. **쓰레기 데이터도 억지로 배정** — 반면 HDBSCAN은 노이즈로 걸러줌

그리고 HDBSCAN의 유일한 약점(고차원)을 **UMAP이 차원축소로 보완**해줍니다.
그래서 셋이 팀입니다 — 이 조합이 바로 **BERTopic** 같은 요즘 라이브러리의 핵심입니다.

#### 잠깐, 임베딩도 차원을 줄이는데 UMAP을 또 하는 이유는?

파이프라인을 보면 차원이 줄어드는 단계가 **두 번(임베딩 → UMAP)** 나옵니다.
"임베딩이 이미 차원을 줄였는데 왜 UMAP을 또?" 싶지만, 두 단계는 **성격이 다릅니다.**

```text
[원본 텍스트]  5만 차원, 희소, 단어 뜻 모름
    │ ① 임베딩(BERT) : "의미를 담으며" 축소 (축소는 부산물, 목적은 의미 부여)
    ▼
[임베딩 벡터]  768차원, 조밀, 의미 O  ← 그래도 HDBSCAN엔 여전히 높음(차원의 저주)
    │ ② UMAP : "이웃 구조를 지키며" 순수 축소 (목적은 밀도 부활)
    ▼
[저차원 벡터]  10차원  ← 밀도 살아남 → HDBSCAN OK ✓
```

| 단계 | 하는 일 | 진짜 목적 |
|---|---|---|
| **① 임베딩** | 5만 → 768차원 | **의미 담기** ("banana"와 "fruit"을 가까운 벡터로) |
| **② UMAP** | 768 → 10차원 | **차원의 저주 해소** (HDBSCAN이 밀도를 찾도록) |

핵심은 임베딩(768차원)이 옛날 방식보다는 훨씬 낮아도 **HDBSCAN의 밀도 계산엔 여전히 높다**는 점입니다.
그래서 UMAP으로 **한 번 더** 낮춰 밀도를 되살립니다.
즉 "차원 축소를 두 번" 이라기보다 **"의미로 한 번 바꾸고(①), 밀도를 위해 한 번 더 줄인다(②)"** 로 보는 게 정확합니다.

> 그렇다고 K-means가 죽은 건 아닙니다. 빠르고 간단하며 그룹 개수를 알 때는 여전히 좋은 선택입니다.
> **"HDBSCAN이 이겼다"가 아니라 "임베딩 시대에 맞는 조합이 HDBSCAN 쪽"** 이 정확한 표현입니다.

## <span style="color:#FEB99C;">4. 차원 축소: 차원의 저주와 그 해법</span>

**차원 축소(Dimensionality Reduction)** 는 데이터를 설명하는 변수(열)의 개수를 줄이는 것인데,
정확히 말하면 그 **주된 목표는 "중요한 정보는 최대한 보존하면서 변수 개수를 줄이는 것"** 입니다.

### NLP에서 흔히 쓰는 차원 축소 방법 5가지

NLP에서 쓰이는 대표 기법은 다음과 같습니다.

| 방법 | 성격 | 한 줄 설명 |
|---|---|---|
| **Embeddings(임베딩)** | 학습 기반 | 수만 개 단어 어휘를 300차원 정도의 조밀한 벡터로 압축 |
| **PCA** | 선형 | 분산이 가장 큰 방향으로 투영 |
| **t-SNE** | 비선형 | 고차원을 2~3D로 시각화 |
| **UMAP** | 비선형 | t-SNE와 비슷하지만 더 빠르고 확장성 좋음 |
| **Topic models (LDA/NMF/LSA)** | 확률·행렬분해 | 문서를 소수의 토픽 분포로 요약 (1편에서 본 방식) |

> 참고: **Bag-of-Words**는 차원 축소가 **아닙니다.** 오히려 고차원 sparse 행렬을 *만드는* 쪽입니다.
> 반대로 임베딩이 차원 축소에 속한다는 점은 놓치기 쉬우니 기억해 두세요.

### 왜 하나만 안 쓰고 여러 기법을 함께 쓸까?

NLP 워크플로우에서는 차원 축소 기법을 **여러 개 이어서** 쓰는 경우가 많습니다.
이유는 단순히 "데이터를 작게 만들려고"가 아니라 — 그건 하나만 써도 얻는 효과입니다 —
**기법마다 잘하는 게 달라서, 각 기법의 강점을 단계별로 활용**하기 위함입니다.

```text
[고차원 텍스트]
    │ ① PCA로 50차원 정도로 1차 축소 (빠름 + 노이즈 제거 + 전역 구조 정리)
    ▼
[중간 차원]
    │ ② t-SNE / UMAP으로 2D 축소 (시각화에 강함)
    ▼
[2D 시각화 📊]
```

PCA는 빠르고 전역 구조를 잘 잡으니 **전처리**에 좋고, t-SNE·UMAP은 **시각화**에 강합니다.
서로 강점이 다르니 조합하면 시너지가 납니다. "각 방법의 강점을 서로 다른 작업/단계에 leverage" 하는 것이죠.

### 왜 차원을 줄여야 하나? — 차원의 저주

> **HDBSCAN은 "밀도(빽빽함)"로 그룹을 찾는데, 고차원에서는 모든 점이 서로 멀어져서 "빽빽한 곳"이 사라진다.**

직관에 반하지만 숫자로 보면 명확합니다. 한 변이 10칸인 공간의 부피는:

```text
1차원(선):    10칸
2차원(면):    100칸
3차원(정육면체): 1,000칸
...
1000차원:     10^1000칸  ← 상상 불가
```

점 개수는 그대로(문서 1만 개)인데 **공간만 폭발**하니, 점들이 광활한 공간에 뿔뿔이 흩어집니다.
사람 1만 명을 100m 복도에 세우면 다닥다닥 붙지만, 우주 전체에 뿌리면 다 외톨이가 되는 것과 같습니다.

더 결정적인 문제는 **거리가 다 비슷해진다**는 것입니다.

```text
저차원(2D):   가장 가까운 이웃 1.2 / 가장 먼 점 8.5  → 차이 큼, 구분 명확 ✓
고차원(1000D): 가장 가까운 이웃 34.7 / 가장 먼 점 35.2 → 차이 미미, 다 비슷 ✗
```

거리는 각 차원의 차이를 다 더해서 계산되는데($\sqrt{d_1^2 + d_2^2 + \cdots + d_{1000}^2}$),
차원이 많으면 수많은 작은 차이들이 **평균으로 뭉개져서** 모든 쌍의 거리가 비슷한 값으로 수렴합니다.

### 그래서 HDBSCAN이 무너진다

HDBSCAN의 3단계(① 밀도 보기 → ② 빽빽한 곳=클러스터 → ③ 외톨이=노이즈)가 고차원에선 다 깨집니다.

| HDBSCAN의 가정 | 고차원에서 벌어지는 일 |
|---|---|
| "빽빽한 곳을 찾자" | 모든 점이 흩어져 빽빽한 곳이 없음 |
| "가까운 이웃끼리 묶자" | 거리가 다 비슷해 이웃을 못 가림 |
| "외톨이는 노이즈" | 다 외톨이처럼 보임 → 다 노이즈 |

데모에서 **80%가 노이즈**로 나온 이유가 바로 이것입니다.
(반면 K-means는 밀도가 아니라 "그나마 제일 가까운 중심"에 억지로라도 배정하므로, 정확하진 않아도 **작동은** 합니다.)

### 차원을 줄이면 밀도가 부활한다

UMAP으로 1000차원 → 10차원으로 줄이면:

```text
【고차원 - 차원의 저주】          【저차원 - 밀도 부활】
   ·      ·                        ····      ·
      ·        ·        UMAP        ······   · ← 노이즈
   ·      ·         ──────────→      ····
     ·  ·      ·                     밀도 살아남
   밀도 = 0                          → "여기가 클러스터!"
   → "다 노이즈" (80%)               → 노이즈 30%로 개선
```

공간이 작아지니 흩어졌던 점들이 다시 뭉치고, "빽빽한 곳"이 생겨 HDBSCAN이 다시 일할 수 있게 됩니다.

## <span style="color:#FEB99C;">5. PCA vs t-SNE vs UMAP: 왜 방법마다 궁합이 다를까?</span>

차원 축소에도 종류가 있고, 그 뒤에 오는 클러스터링·목적과 **궁합**이 맞아야 합니다.

> **PCA는 "직선자"로 데이터를 재는데, 의미 데이터는 휘어져 있다. UMAP은 "휘어진 자"라서 그 곡면을 따라갈 수 있다.**

### PCA (선형)

데이터에서 **분산이 가장 큰 방향(직선)** 을 찾아 거기에 투영(그림자 뜨기)합니다.
표준화 → 공분산 행렬 → 고유값/고유벡터 계산 순서로 진행되며, 고유벡터들은 서로 **직교(무상관)** 합니다.

PCA의 장단점을 표로 정리하면 다음과 같습니다. (둘 다 각각 네 가지가 모두 성립합니다.)

| 👍 장점 | 👎 단점 |
|---|---|
| **간단하고 빠름** (선형대수 기반) | **개별 성분 해석이 어려움** (여러 변수의 혼합이라 축의 의미가 모호) |
| **직교(무상관) 성분 생성** → 중복 정보 제거 | **중요한 예외(edge case) 변동을 잃을 수 있음** |
| **결정론적 결과** (항상 같은 결과, 랜덤성 없음) | **선형 관계만 가정** (비선형 패턴은 못 잡음) |
| **노이즈 제거** (분산 작은 성분 = 잡음을 버림) | **이상치·스케일에 민감** → 사전 표준화 필수 |
| **전역 구조(큰 그림)를 잘 보존** | |

### t-SNE (비선형, 시각화 전용)

t-SNE는 고차원 데이터(예: 300차원 단어 임베딩)를 **2~3차원으로 압축해 사람이 눈으로 보게** 만드는 기법입니다.
비슷한 점끼리 가깝게 모아 그려줍니다.

```text
[300차원 단어 임베딩]  ── t-SNE ──▶  2D 산점도 📊 (비슷한 단어끼리 뭉쳐 보임)
```

- 👍 고차원 구조를 직관적인 그림으로 보여줌 (시각화의 강자)
- 👎 **비결정론적**(실행마다 결과 다름), **계산 비용 큼(느림)**, **대부분의 전처리에 부적합**

여기서 자주 하는 오해:

- t-SNE 결과는 거리·전역 구조가 왜곡되므로 **클러스터링 입력이나 전처리로는 부적합**합니다. 그 용도엔 PCA가 낫습니다.

> t-SNE의 주 용도는 **오직 "고차원 데이터의 시각화"** 라고 기억하면 좋습니다.

### UMAP (비선형)

데이터가 놓인 **곡면(manifold)** 을 따라가며 축소합니다.
가까운 이웃들로 그래프를 만들어, "원래 가까웠던 점은 축소 후에도 가깝게" 관계를 유지합니다.
(이름 자체가 **U**niform **M**anifold **A**pproximation and **P**rojection)

- 👍 **지역+전역 구조 보존**, 비선형, **확장성 좋음(t-SNE보다 빠름)**
- 👎 비결정론적, 튜닝 필요, 해석 어려움

#### UMAP이 t-SNE보다 시각화 도구로서 나은 점

t-SNE와 UMAP은 **둘 다 시각화가 주 목적인 비선형 차원 축소**로, 사실상 같은 부류입니다.
UMAP은 그 안에서 **더 개선된 버전**이라고 보면 됩니다.

| 구분 | t-SNE | UMAP |
|---|---|---|
| 속도 | 느림 | **빠름** ✅ |
| 확장성 | 큰 데이터에 약함 | **큰 데이터에 강함** ✅ |
| 전역 구조 보존 | 약함(국소 위주) | **상대적으로 더 잘 보존** |
| 공통점 | 둘 다 비선형·시각화용·비결정론적·**거리 왜곡 있음** | |

즉 UMAP의 핵심 장점은 **"t-SNE와 같은 일을 더 빠르고 확장성 있게 해낸다"** 는 것입니다.

> 정리하면:
> - **시각화용 비선형 차원 축소** → t-SNE, UMAP
> - **전처리·클러스터링 전 차원 축소** → PCA (거리·전역 구조 보존, 결정론적)

### 무엇을 보존하느냐가 궁합을 결정한다

이게 핵심입니다.

```text
HDBSCAN이 필요한 것 = "누가 누구랑 가까운가" (지역/이웃 정보)
UMAP이 보존하는 것  = "누가 누구랑 가까운가" (지역/이웃 정보)  ← 딱 맞음! ✓
PCA가 보존하는 것   = "전체적인 큰 방향"      (지역 정보는 뭉갤 수 있음) ✗
```

그래서 데모가 이렇게 짝지어진 것입니다.

| 데모 | 조합 | 이유 |
|---|---|---|
| B4~B5 | **K-means + PCA** | K-means는 거리·중심 기반 → PCA의 선형 투영과 잘 맞음 |
| B6~B7 | **HDBSCAN + UMAP** | HDBSCAN은 밀도·이웃 기반 → UMAP의 이웃 보존과 딱 맞음 |

> *"K-means로 클러스터를 만든 뒤 UMAP으로 축소하는 건 하지 마라. 서로 맞지 않는다."*
> 즉 **아무거나 섞으면 안 되고, 방법마다 궁합이 있다**는 것입니다.

### ⚠️ 오해했던 점: "UMAP은 거리를 왜곡하니까 DBSCAN이랑 어울린다"?

- **PCA ↔ K-means**: 맞습니다. PCA가 **거리를 잘 보존**하고, K-means는 정확한 거리가 필요하니 궁합이 좋습니다.
- **UMAP ↔ HDBSCAN**: 자주 함께 쓰이는 건 맞지만, 그 이유가 **"거리를 왜곡해서"가 아니라, "이웃 구조를 보존"하기 때문입니다.**

DBSCAN·HDBSCAN도 결국 "반경 안에 점이 몇 개냐"를 보는 **거리·밀도 기반** 알고리즘입니다.
따라서 거리 왜곡은 HDBSCAN에게도 **나쁜 소식**이지, 어울리는 이유가 될 수 없습니다.

UMAP-HDBSCAN이 어울리는 진짜 이유는 **UMAP이 "국소 이웃 구조(누가 누구랑 가까운가)를 잘 보존"** 하기 때문입니다.
HDBSCAN이 원하는 정보(밀도·이웃)를 UMAP이 지켜주니 궁합이 맞는 것이지, 거리를 왜곡해서가 아닙니다.

> 요컨대 "왜곡"은 어느 거리 기반 클러스터링에게도 손해입니다.
> UMAP·t-SNE 결과를 **거리 기반 클러스터링에 그대로 넣는 것은 항상 조심**해야 합니다.
> 궁합의 근거는 "왜곡"이 아니라 **"이웃 구조 보존"** 이라는 점을 기억하세요.

## <span style="color:#FEB99C;">6. 실습 데모: 클러스터링 (Demo B, sklearn)</span>

토픽 모델링(1편)과 **같은 CFPB 불만 데이터**를 사용하되,
클러스터링은 정수 카운트가 필요 없으므로 **TF-IDF** 를 씁니다.

```python
from sklearn.cluster import MiniBatchKMeans as KMeans
from sklearn.metrics import silhouette_score

# 클러스터링은 정수 카운트 불필요 → TF-IDF 사용
km = KMeans(n_clusters=20, random_state=123, reassignment_ratio=0.05)
labels = km.fit_predict(dtm)   # fit_predict → 문서당 레이블 1개

# 개별 클러스터 해석 3가지: ① 단어 빈도 ② cluster_centers_ 표준화 ③ transform() 거리로 최근접 문서
distances = km.transform(dtm)  # 각 문서 → 20개 중심까지 거리
```

```python
# 차원 축소 + HDBSCAN
from hdbscan import HDBSCAN
import umap

hdb = HDBSCAN().fit_predict(dtm)          # 원본: 80% 노이즈(-1), 135 클러스터 ← 차원의 저주
reduced = umap.UMAP(n_components=10, n_neighbors=15,
                    metric='cosine').fit_transform(dtm)
hdb = HDBSCAN().fit_predict(reduced)      # UMAP 후: 30% 노이즈로 개선
```

- **클러스터 해석** : 회사명(Wells Fargo 등)이 클러스터를 형성 → **NER로 "bank"로 치환**하는 팁
- **차원축소** : 표준화 + PCA(누적 분산 **75%** → 357개 성분). 4가지 DTM 준비(원본/표준화/PCA/PCA+표준화)
- **K-means 튜닝** : `range(10, 101, 5)`, 실루엣 점수로 평가 → **PCA + k=55** 정도가 좋음
- **HDBSCAN 튜닝** : 최적화 지표가 마땅치 않아, 노이즈 수·클러스터 수·최대 크기·표준편차·최소크기 클러스터 수 등 **5가지를 직접 관찰**
  - 튜닝 파라미터: `cluster_selection_method`(eom/leaf), `min_cluster_size`, `min_samples`, `cluster_selection_epsilon`
  - `**params` 딕셔너리 언패킹, `record = input_params.copy()` 로 설정 기록

## <span style="color:#FEB99C;">7. 최종 정리</span>

> 클러스터링의 핵심은 **"문서를 하나의 그룹으로 분류하되, 데이터 특성(차원·모양)에 맞는 방법과 전처리를 골라야 한다"** 는 것입니다.

2편에서 배운 것을 정리하면:

- **클러스터링 ↔ 토픽 모델링**은 대체가 아니라 **보완** 관계. 토픽 분포 벡터를 클러스터링에 넣어 문서를 한 단계 더 그룹화
- **K-means**(개수 지정, 다 배정, 구형, 지역 최솟값 위험) vs **HDBSCAN**(자동, 노이즈 허용, 자유 모양, 세분화 조절 가능)
- **실루엣 점수** : +1=잘 배정, 0=경계, **−1=다른 군집에 더 가까움(잘못 배정, outlier 아님)**
- **HDBSCAN이 요즘 방식**인 건 알고리즘이 아니라 **의미 임베딩의 등장** 덕분. 임베딩 → UMAP → HDBSCAN 파이프라인(BERTopic)
  - 이때 차원 축소가 두 번인 건 성격이 달라서 — **① 임베딩 = 의미 담기, ② UMAP = 밀도 부활(차원의 저주 해소)**
- **차원 축소의 목표** = "정보 보존 + 변수 축소". NLP 5대 방법 = 임베딩·PCA·t-SNE·UMAP·토픽모델
- **여러 기법을 조합**하는 이유 = 각 기법의 강점(PCA=전처리, t-SNE/UMAP=시각화)을 단계별로 활용
- **차원의 저주** = 고차원에선 거리가 다 비슷해져 밀도가 사라짐 → HDBSCAN이 무너짐 → **차원축소로 밀도 부활**
- **PCA(선형·전역·전처리용) vs t-SNE/UMAP(비선형·지역·시각화용)** — 뒤에 오는 목적과 **궁합**을 맞춰야 함 (K-means↔PCA, HDBSCAN↔UMAP)
- 궁합의 근거는 "거리 왜곡"이 아니라 **"어떤 구조를 보존하느냐"**. UMAP은 이웃 구조를 보존해 HDBSCAN과 맞고, 거리 왜곡은 어느 거리 기반 클러스터링에도 손해
- Demo B에서 TF-IDF 기반 K-means와 HDBSCAN을 비교하고, 차원 축소로 노이즈를 80% → 30%로 개선
