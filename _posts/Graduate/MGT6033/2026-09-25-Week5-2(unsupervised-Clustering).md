## <span style="color:#FEB99C;">1. 클러스터 분석: 문서를 그룹으로 나누기</span>

1편의 **같은 불만 데이터**, 이번엔 미션이 조금 다릅니다.
"불만들을 **그룹으로 나눠서** 후속 조치 담당을 배정하라."

토픽 모델링이 "무슨 주제들이 섞여 있나"를 봤다면, 클러스터링은 "비슷한 것끼리 묶기"에 집중합니다.
클러스터링 방법을 고를 때 던지는 질문들:

- 내 데이터는 무엇인가? (단어 카운트? 토픽? 임베딩?)
- 클러스터가 몇 개인가? (개수를 아는가?)
- **거리(distance)** 는 어떻게 잴 것인가? (코사인? 유클리드?)

클러스터링 접근은 크게 세 가지로 나뉩니다.

| 유형 | 원리 | 특징 |
|---|---|---|
| **Centroid 기반** | 중심점에서 원/구를 그림 | 가장 직관적, **구형(spherical)만**, 유클리드 거리 |
| **Hierarchical(계층적)** | 유사한 쌍/이웃으로 트리 구성 | 상향식(agglomerative)·하향식(divisive), 유연함 |
| **Density(밀도) 기반** | 점이 빽빽한 곳을 찾음 | **어떤 모양이든** OK, 노이즈 허용 |

> 클러스터링의 어려움들:
> ① 해석이 어려움(토픽 모델과 달리 레이블 숫자만 나옴) ② **차원의 저주** ③ 계산 비용 ④ 초기화 무작위성 → 불안정 ⑤ 품질 평가가 주관적

## <span style="color:#FEB99C;">2. K-means & HDBSCAN</span>

### K-means: 중심에서부터 원을 그린다

가장 원조격인 클러스터링입니다. 절차는 단순합니다.

1. 클러스터 개수 $K$ 를 정하고, $K$ 개의 중심점을 **무작위로** 찍는다
2. 각 점을 **가장 가까운 중심**에 배정한다 (유클리드 거리)
3. 배정된 점들의 중심으로 **중심점을 다시 계산**한다
4. 중심이 거의 안 움직일 때까지 2~3을 반복한다

> 중심점에서 거리로 배정하다 보니 **클러스터 모양이 항상 구형**이 됩니다.
> 또한 유클리드 거리를 쓰므로 **데이터 표준화(standardization)** 가 필수입니다.

- 👍 직관적, 빠름(특히 mini-batch 버전)
- 👎 **구형만** 잡음, 불안정(초기값 의존), 지역 최솟값(local minimum)에 빠질 위험

K-means의 평가 지표는 풍부합니다.

| 지표 | 방향 | 의미 |
|---|---|---|
| **WCSS/Inertia (Elbow)** | 꺾이는 지점 | 군집 내 제곱합 |
| **Calinski-Harabasz** | 높을수록 좋음 | 군집 간 분산 / 군집 내 분산 |
| **Davies-Bouldin** | 낮을수록 좋음 | 클러스터 분리도 |
| **Silhouette** | +1에 가까울수록 좋음 | 음수면 다른 클러스터에 더 가깝다는 뜻 |

### HDBSCAN: 빽빽하게 모인 곳을 그룹으로

이름이 길지만 뜯어보면 됩니다 — *Hierarchical Density-Based Spatial Clustering of Applications with Noise*.

- **Density 기반** : 중심점이 아니라 **점들의 밀도(빽빽함)** 로 클러스터 정의
- **Hierarchical** : 트리를 만들어 클러스터를 병합/분할
- **Noise** : 모든 점을 억지로 배정하지 않고, 안 맞는 건 **노이즈(-1)** 로 버림

- 👍 **클러스터 개수를 지정할 필요 없음**, 노이즈 허용, 자유로운 모양
- 👎 **고차원에서 약함**(차원의 저주), 레이블 해석 어려움, 품질 평가 어려움

## <span style="color:#FEB99C;">3. K-means vs HDBSCAN, 그리고 요즘 실무 방식</span>

두 방법은 철학이 완전히 다릅니다.

| | **K-means** | **HDBSCAN** |
|---|---|---|
| 그룹 개수 | **내가 지정** ("20개") | **자동으로 찾음** |
| 모든 문서 배정? | **무조건 배정** | **노이즈 허용** (-1로 버림) |
| 그룹 모양 | 구형만 | 아무 모양 |

### "요즘은 HDBSCAN이 실무 방식"이라는데, 왜?

여기엔 중요한 오해가 하나 있습니다. 데모에서 **HDBSCAN을 그냥 텍스트에 돌리면 80%가 노이즈**로 나왔습니다.
즉 "HDBSCAN 자체가 K-means를 이겼다"가 **아닙니다.**

진짜 이유는 **입력 데이터가 바뀌었기 때문**입니다.

```text
[옛날] 텍스트 → 단어 세기(DTM/TF-IDF) → 클러스터링
              └ 1000차원, 희소, 단어 뜻 모름

[요즘] 텍스트 → 문장 임베딩(BERT 등) → UMAP → HDBSCAN
              └ 의미를 담은 조밀한 벡터
```

**의미 임베딩의 등장**이 게임체인저였고, 이 임베딩과 궁합이 맞는 게 HDBSCAN이었던 것이죠.
K-means가 임베딩 시대에 불리한 이유:

1. **구형 그룹만 만든다** — 의미 공간의 주제들은 길쭉하거나 휘어져 있음
2. **그룹 개수를 미리 정해야 한다** — 실무에선 주제 개수를 아무도 모름
3. **쓰레기 데이터도 억지로 배정** — 반면 HDBSCAN은 노이즈로 걸러줌

그리고 HDBSCAN의 유일한 약점(고차원)을 **UMAP이 차원축소로 보완**해줍니다.
그래서 셋이 팀입니다 — 이 조합이 바로 **BERTopic** 같은 요즘 라이브러리의 핵심입니다.

> 그렇다고 K-means가 죽은 건 아닙니다. 빠르고 간단하며 그룹 개수를 알 때는 여전히 좋은 선택입니다.
> **"HDBSCAN이 이겼다"가 아니라 "임베딩 시대에 맞는 조합이 HDBSCAN 쪽"** 이 정확한 표현입니다.

## <span style="color:#FEB99C;">4. 차원 축소: 차원의 저주와 그 해법</span>

**차원 축소(Dimensionality Reduction)** 는 데이터를 설명하는 변수(열)의 개수를 줄이는 것입니다.
NLP에서 쓰이는 대표 기법은 임베딩, PCA, 토픽 모델링, t-SNE, UMAP 등이 있습니다.

### 왜 차원을 줄여야 하나? — 차원의 저주

> **HDBSCAN은 "밀도(빽빽함)"로 그룹을 찾는데, 고차원에서는 모든 점이 서로 멀어져서 "빽빽한 곳"이 사라진다.**

직관에 반하지만 숫자로 보면 명확합니다. 한 변이 10칸인 공간의 부피는:

```text
1차원(선):    10칸
2차원(면):    100칸
3차원(정육면체): 1,000칸
...
1000차원:     10^1000칸  ← 상상 불가
```

점 개수는 그대로(문서 1만 개)인데 **공간만 폭발**하니, 점들이 광활한 공간에 뿔뿔이 흩어집니다.
사람 1만 명을 100m 복도에 세우면 다닥다닥 붙지만, 우주 전체에 뿌리면 다 외톨이가 되는 것과 같습니다.

더 결정적인 문제는 **거리가 다 비슷해진다**는 것입니다.

```text
저차원(2D):   가장 가까운 이웃 1.2 / 가장 먼 점 8.5  → 차이 큼, 구분 명확 ✓
고차원(1000D): 가장 가까운 이웃 34.7 / 가장 먼 점 35.2 → 차이 미미, 다 비슷 ✗
```

거리는 각 차원의 차이를 다 더해서 계산되는데($\sqrt{d_1^2 + d_2^2 + \cdots + d_{1000}^2}$),
차원이 많으면 수많은 작은 차이들이 **평균으로 뭉개져서** 모든 쌍의 거리가 비슷한 값으로 수렴합니다.

### 그래서 HDBSCAN이 무너진다

HDBSCAN의 3단계(① 밀도 보기 → ② 빽빽한 곳=클러스터 → ③ 외톨이=노이즈)가 고차원에선 다 깨집니다.

| HDBSCAN의 가정 | 고차원에서 벌어지는 일 |
|---|---|
| "빽빽한 곳을 찾자" | 모든 점이 흩어져 빽빽한 곳이 없음 |
| "가까운 이웃끼리 묶자" | 거리가 다 비슷해 이웃을 못 가림 |
| "외톨이는 노이즈" | 다 외톨이처럼 보임 → 다 노이즈 |

데모에서 **80%가 노이즈**로 나온 이유가 바로 이것입니다.
(반면 K-means는 밀도가 아니라 "그나마 제일 가까운 중심"에 억지로라도 배정하므로, 정확하진 않아도 **작동은** 합니다.)

### 차원을 줄이면 밀도가 부활한다

UMAP으로 1000차원 → 10차원으로 줄이면:

```text
【고차원 - 차원의 저주】          【저차원 - 밀도 부활】
   ·      ·                        ····      ·
      ·        ·        UMAP        ······   · ← 노이즈
   ·      ·         ──────────→      ····
     ·  ·      ·                     밀도 살아남
   밀도 = 0                          → "여기가 클러스터!"
   → "다 노이즈" (80%)               → 노이즈 30%로 개선
```

공간이 작아지니 흩어졌던 점들이 다시 뭉치고, "빽빽한 곳"이 생겨 HDBSCAN이 다시 일할 수 있게 됩니다.

## <span style="color:#FEB99C;">5. PCA vs UMAP: 왜 방법마다 궁합이 다를까?</span>

차원 축소에도 종류가 있고, 그 뒤에 오는 클러스터링과 **궁합**이 맞아야 합니다.

> **PCA는 "직선자"로 데이터를 재는데, 의미 데이터는 휘어져 있다. UMAP은 "휘어진 자"라서 그 곡면을 따라갈 수 있다.**

### PCA (선형)

데이터에서 **분산이 가장 큰 방향(직선)** 을 찾아 거기에 투영(그림자 뜨기)합니다.
표준화 → 공분산 행렬 → 고유값/고유벡터 계산 순서로 진행되며, 고유벡터들은 서로 **직교(무상관)** 합니다.

- 👍 빠름, 결정론적(항상 같은 결과), **전역 구조(큰 그림)** 를 잘 보존
- 👎 **직선 관계만** 잡음, 선형 가정, 해석 어려움

### UMAP (비선형)

데이터가 놓인 **곡면(manifold)** 을 따라가며 축소합니다.
가까운 이웃들로 그래프를 만들어, "원래 가까웠던 점은 축소 후에도 가깝게" 관계를 유지합니다.
(이름 자체가 **U**niform **M**anifold **A**pproximation and **P**rojection)

- 👍 **지역+전역 구조 보존**, 비선형, 확장성 좋음
- 👎 비결정론적, 튜닝 필요, 해석 어려움

### 무엇을 보존하느냐가 궁합을 결정한다

이게 핵심입니다.

```text
HDBSCAN이 필요한 것 = "누가 누구랑 가까운가" (지역/이웃 정보)
UMAP이 보존하는 것  = "누가 누구랑 가까운가" (지역/이웃 정보)  ← 딱 맞음! ✓
PCA가 보존하는 것   = "전체적인 큰 방향"      (지역 정보는 뭉갤 수 있음) ✗
```

그래서 데모가 이렇게 짝지어진 것입니다.

| 데모 | 조합 | 이유 |
|---|---|---|
| B4~B5 | **K-means + PCA** | K-means는 거리·중심 기반 → PCA의 선형 투영과 잘 맞음 |
| B6~B7 | **HDBSCAN + UMAP** | HDBSCAN은 밀도·이웃 기반 → UMAP의 이웃 보존과 딱 맞음 |

> *"K-means로 클러스터를 만든 뒤 UMAP으로 축소하는 건 하지 마라. 서로 맞지 않는다."*
> 즉 **아무거나 섞으면 안 되고, 방법마다 궁합이 있다**는 것입니다.

## <span style="color:#FEB99C;">6. 실습 데모: 클러스터링 (Demo B, sklearn)</span>

토픽 모델링(1편)과 **같은 CFPB 불만 데이터**를 사용하되,
클러스터링은 정수 카운트가 필요 없으므로 **TF-IDF** 를 씁니다.

```python
from sklearn.cluster import MiniBatchKMeans as KMeans
from sklearn.metrics import silhouette_score

# 클러스터링은 정수 카운트 불필요 → TF-IDF 사용
km = KMeans(n_clusters=20, random_state=123, reassignment_ratio=0.05)
labels = km.fit_predict(dtm)   # fit_predict → 문서당 레이블 1개

# 개별 클러스터 해석 3가지: ① 단어 빈도 ② cluster_centers_ 표준화 ③ transform() 거리로 최근접 문서
distances = km.transform(dtm)  # 각 문서 → 20개 중심까지 거리
```

```python
# 차원 축소 + HDBSCAN
from hdbscan import HDBSCAN
import umap

hdb = HDBSCAN().fit_predict(dtm)          # 원본: 80% 노이즈(-1), 135 클러스터 ← 차원의 저주
reduced = umap.UMAP(n_components=10, n_neighbors=15,
                    metric='cosine').fit_transform(dtm)
hdb = HDBSCAN().fit_predict(reduced)      # UMAP 후: 30% 노이즈로 개선
```

- **클러스터 해석** : 회사명(Wells Fargo 등)이 클러스터를 형성 → **NER로 "bank"로 치환**하는 팁
- **차원축소** : 표준화 + PCA(누적 분산 **75%** → 357개 성분). 4가지 DTM 준비(원본/표준화/PCA/PCA+표준화)
- **K-means 튜닝** : `range(10, 101, 5)`, 실루엣 점수로 평가 → **PCA + k=55** 정도가 좋음
- **HDBSCAN 튜닝** : 최적화 지표가 마땅치 않아, 노이즈 수·클러스터 수·최대 크기·표준편차·최소크기 클러스터 수 등 **5가지를 직접 관찰**
  - 튜닝 파라미터: `cluster_selection_method`(eom/leaf), `min_cluster_size`, `min_samples`, `cluster_selection_epsilon`
  - `**params` 딕셔너리 언패킹, `record = input_params.copy()` 로 설정 기록

## <span style="color:#FEB99C;">7. 최종 정리</span>

> 클러스터링의 핵심은 **"문서를 하나의 그룹으로 분류하되, 데이터 특성(차원·모양)에 맞는 방법과 전처리를 골라야 한다"** 는 것입니다.

2편에서 배운 것을 정리하면:

- **K-means**(개수 지정, 다 배정, 구형) vs **HDBSCAN**(자동, 노이즈 허용, 자유 모양)
- **HDBSCAN이 요즘 방식**인 건 알고리즘이 아니라 **의미 임베딩의 등장** 덕분. 임베딩 → UMAP → HDBSCAN 파이프라인(BERTopic)
- **차원의 저주** = 고차원에선 거리가 다 비슷해져 밀도가 사라짐 → HDBSCAN이 무너짐 → **차원축소로 밀도 부활**
- **PCA(선형·전역) vs UMAP(비선형·지역)** — 뒤에 오는 클러스터링이 원하는 정보와 **궁합**을 맞춰야 함 (K-means↔PCA, HDBSCAN↔UMAP)
