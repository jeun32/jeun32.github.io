## <span style="color:#FEB99C;">1. 비지도 vs 지도 학습</span>

머신러닝은 크게 **지도 학습**과 **비지도 학습**으로 나뉩니다.

| 구분 | 지도 학습(Supervised) | 비지도 학습(Unsupervised) |
|---|---|---|
| 데이터 | X(입력) + **Y(레이블)** | **X(입력)만** |
| 목적 | 레이블을 예측·분류 | 데이터의 **자연스러운 구조**를 스스로 발견 |
| 예시 | 과일 사진에 "사과/바나나" 레이블을 붙여 학습 | 특징을 보고 알아서 그룹을 형성 |

지도 학습은 사과·바나나 사진에 **정답 레이블**을 달아 "이렇게 분류해라"라고 가르치는 것이고,
비지도 학습은 레이블 없이 **"알아서 비슷한 것끼리 묶어봐"** 라고 시키는 것입니다.

> 경험칙: 가능하면 **지도 학습을 먼저 고려**하세요.
> 사람처럼 생각하도록 기계를 훈련시킬 수 있다면, 그게 거의 항상 비지도 모델보다 더 나은 결과를 냅니다.

사실 우리는 이미 비지도 학습을 접했습니다. **워드 임베딩(word2vec)** 이 대표적이죠.
모델은 `happy`와 `elated`가 "긍정적"이라는 걸 배우는 게 아니라, 단지 **비슷한 맥락에서 쓰인다**는 걸 학습합니다.
레이블을 주지 않았으니 정의상 비지도 학습입니다.

문서 수준에서 자연어에 자주 쓰이는 비지도 학습은 크게 두 가지입니다.

- **토픽 모델링** : 코퍼스 전반의 **잠재적 주제(latent topic)** 를 찾고, 각 문서에 얼마나 관련 있는지 수치화
- **클러스터링** : 문서 전체를 **하나의 그룹**으로 분류

이 둘의 차이가 이번 주 내용의 핵심이라, 6장에서 따로 자세히 다루겠습니다.

### 🔎 헷갈리기 쉬운 포인트: "정답(레이블)이 필요한가?"로 판단하기

지도/비지도를 가르는 기준은 딱 하나, **"정답(레이블)이 필요한가?"** 입니다.
NLP 작업들을 이 기준으로 분류하면 아래처럼 깔끔하게 갈립니다.

| NLP 작업 | 분류 | 이유 |
|---|---|---|
| Topic Modeling (토픽 모델링) | **비지도** | 레이블 없이 문서에서 주제를 스스로 찾음 |
| Clustering (군집화) | **비지도** | 레이블 없이 비슷한 것끼리 묶음 |
| Sentiment Classification (감성 분류) | 지도 | "긍정/부정" 정답 레이블로 학습 |
| Named Entity Recognition (개체명 인식) | 지도 | 어떤 단어가 인명/지명인지 레이블 필요 |

> 핵심 한 줄: **정답(레이블)이 필요하면 지도, 필요 없으면 비지도.**
> "분류(classification)" 계열은 대부분 지도, "발견·군집·분해" 계열은 대부분 비지도입니다.

## <span style="color:#FEB99C;">2. 토픽 모델링: 문서 속 주제를 캐내기</span>

**비즈니스 시나리오**로 시작해봅시다.
당신은 갓 입사한 고객 관리 매니저이고, IT팀이 **고객 불만 10만 건**을 던져줍니다.
"이 불만들의 **공통 테마**와 각 테마의 **비중**을 일주일 안에 보고하라"는 임무를 받았습니다.

선택지는 세 가지 정도입니다.

| 방법 | 장점 | 단점 |
|---|---|---|
| 팀원에게 나눠 읽히기 | 사람이 전부 읽음 | 매우 느림, 사람마다 다르게 분류 |
| 샘플만 읽고 키워드 검색 | 덜 느림, 어느 정도 객관적 | 드문 이슈를 놓칠 수 있음, 여전히 주관적 |
| **토픽 모델링으로 자동화** | 전체 코퍼스 활용, 분석자 편향 ↓ | 완전 객관은 아님(해석 필요) |

> 💡 **수동/키워드 기반 분류의 한계 정리**
> 위 표의 앞 두 방법(사람이 직접, 키워드 검색)이 대규모 코퍼스에서 갖는 약점은 세 가지로 요약됩니다.
> 1. **느림(time-consuming)** — 사람이 일일이 규칙을 만들고 분류
> 2. **놓침(missing rare issues)** — 미리 정한 키워드에 없는 희귀·신규 패턴을 못 잡음
> 3. **주관성(subjectivity)** — 분석가마다 기준이 달라 결과가 흔들림

토픽 모델링의 **핵심 단계**는 다음과 같습니다.

1. **전처리** : 숫자·구두점 제거, 표제어추출/어간추출 (품질이 여기서 갈림)
2. **특징 추출** : 텍스트를 숫자로 → Bag-of-Words(DTM) 또는 TF-IDF
3. **모델 선택** : LDA, NMF 등
4. **훈련·튜닝** : 특히 **토픽 개수**를 직접 정해야 함
5. **평가·전달** : 시각화로 결과 소통

> ⚠️ **전처리를 대충 하면?** 토픽 모델의 품질(해석 가능성·정확도)이 떨어집니다.
> 불용어·노이즈를 제대로 걸러내지 못하면 토픽이 뒤죽박죽 섞여 해석이 어려워집니다.

### 토픽 모델링이 내놓는 결과물(output)은?

토픽 모델링을 돌리면 대표적으로 **두 가지**가 나옵니다.

- **① 토픽 집합** : 코퍼스 전체에서 "어떤 주제들이 있는지"의 목록 (예: 스포츠, 정치, 경제…)
- **② 문서별 토픽 관련도 점수** : 각 문서가 각 토픽에 얼마나 걸쳐 있는지 (예: 문서A = 스포츠 70% + 경제 20% + 정치 10%)

반대로, 아래 두 가지는 토픽 모델링의 결과물이 **아닙니다.**

- ❌ "문서당 단일 레이블" → 이건 **분류(classification)** 의 출력물
- ❌ "코퍼스의 모든 고유 단어 목록" → 이건 그냥 어휘 사전(vocabulary)일 뿐

> 정리: 토픽 모델링에서 한 문서는 **여러 토픽에 동시에** 걸칠 수 있고,
> 그래서 "레이블 1개"가 아니라 **"토픽별 관련도 점수"** 를 받습니다. 그리고 **토픽 개수는 사용자가 직접 지정**합니다.

### 토픽 품질은 어떻게 평가하나?

토픽 모델은 "잘 맞았다"를 판단하기가 애매합니다. 두 수준에서 봅니다.

- **모델 수준** : **Perplexity**(회귀의 SSE와 유사한 개념)
- **토픽 수준** : **Coherence**(단어들이 함께 등장할 확률 → PMI, U_mass 등), 그리고 사람이 하는 **Word Intrusion Task**

> Word Intrusion Task란? 한 토픽의 상위 단어 4개 + 무작위 침입 단어 1개를 섞어놓고,
> **사람에게** "안 어울리는 단어"를 고르게 합니다. 토픽이 잘 뭉쳐있다면 침입자가 **한눈에 보여야** 합니다.

#### 📊 평가 지표 3종 한눈에 비교

세 지표는 각각 **"무엇을 측정하는가"** 와 **"누가 평가하는가(자동 vs 사람)"** 가 다릅니다.

| 지표 | 무엇을 측정 | 방향 | 평가 주체 | 특징 |
|---|---|---|---|---|
| **Perplexity** | 모델의 예측력 (안 본 문서를 얼마나 잘 예측) | **낮을수록 좋음 ↓** | 자동(수학) | 계산은 쉽지만, 사람이 느끼는 토픽 품질과 종종 불일치 |
| **Coherence** | 토픽 내 단어들의 의미적 응집도 | **높을수록 좋음 ↑** | 자동(통계) | 단어 동시 출현 기반. 사람 판단과 잘 맞아 실무에서 애용 |
| **Word Intrusion** | 토픽의 해석 가능성 | 침입자를 잘 찾을수록 좋음 | **사람(human)** | 직관적이지만 사람 손이 많이 감 |

- **Perplexity** 🎓 : 시험을 잘 예습한 학생이 덜 헤매듯, 값이 낮을수록 모델이 데이터를 잘 "예습"한 것.
- **Coherence** 🍎 : `사과·바나나·포도·오렌지`처럼 한 주제로 뭉치면 높음 / `사과·자동차·대통령`처럼 뒤죽박죽이면 낮음.
- **Word Intrusion** 👤 : `사과, 바나나, [자동차], 포도`에서 사람이 침입자(자동차)를 **쉽게 골라내면** 잘 만들어진 토픽.

> ⚠️ Word Intrusion Task의 주체는 **모델이 아니라 "사람(human)"** 입니다.
> "모델이 이상한 단어를 찾아내는지 테스트"라고 오해하기 쉬운데, **사람의 직관**으로 토픽이 이해 가능한지 검증하는 방법입니다. (토픽이 잘 만들어졌는지 사람이 검증)
>
> 참고로 지도 학습의 지표인 **F1 score는 토픽 모델링에 쓸 수 없습니다.** 토픽 모델링은 정답 레이블이 없는 비지도 학습이기 때문입니다.

## <span style="color:#FEB99C;">3. LDA & NMF: 토픽 모델링의 두 엔진</span>

### LDA (Latent Dirichlet Allocation)

가장 널리 쓰이는 토픽 모델링 기법입니다. 이름을 뜯어보면 원리가 보입니다.

| 단어 | 의미 |
|---|---|
| **Latent** | 숨겨진(잠재적인) 것 → 즉 **토픽** |
| **Dirichlet** | 베이지안 통계에서 쓰는 다변량 확률 분포 → **사전 분포(prior)** 로 사용 |
| **Allocation** | 토픽이 문서에 어떻게 **배분**되는가 |

LDA는 **생성 과정(generative process)** 을 가정합니다.
"저자가 먼저 어떤 토픽에 대해 쓸지 고르고 → 그 토픽에 맞는 단어들을 골라 문서를 쓴다"는 것이죠.

LDA 생성 과정의 **핵심 가정**을 정리하면:

- 각 **단어**는 각 토픽 안에서 어떤 **확률**로 등장한다 (토픽 = 단어들에 대한 확률 분포)
- 각 **토픽**은 각 문서 전체에 걸쳐 어떤 **확률**로 등장한다 (문서 = 토픽들에 대한 확률 분포)
- 단어·토픽 분포는 **디리클레 사전분포(Dirichlet priors)** 의 지배를 받는다
- ❌ "각 문서는 오직 하나의 토픽만 포함한다"는 **틀린 가정** — LDA의 핵심은 **한 문서에 여러 토픽이 혼합**된다는 것

> **디리클레 분포의 역할**: 토픽·단어 분포에 대한 **사전분포(prior)** 입니다.
> 쉽게 말해 "분포들의 분포" — 문서마다 토픽 분포, 토픽마다 단어 분포를 만들어낼 때 그 **출발점(사전 믿음)** 이 되어줍니다.
> (관측된 단어를 직접 생성하거나, 문서 개수를 정하거나, 모델 적합도를 평가하는 역할이 **아닙니다.**)

주요 하이퍼파라미터는 두 개의 Dirichlet 사전입니다.

- **Alpha (문서-토픽 사전)** : 문서 안의 토픽 분포 모양을 조절
- **Beta (토픽-단어 사전)** : 토픽 안의 단어 분포 모양을 조절

#### 🔑 Alpha / Beta 완전 정리

Alpha와 Beta는 이름이 비슷해 자주 헷갈립니다. **"무엇의 사전분포인가"** 와 **"크면 어떻게 되는가"** 두 축으로 잡으면 됩니다.

| | **Alpha (α)** | **Beta (β)** |
|---|---|---|
| 무엇의 사전분포? | **문서 → 토픽** 분포 | **토픽 → 단어** 분포 |
| 담당 | 한 문서가 어떤 토픽들을 가질지 | 한 토픽이 어떤 단어들을 가질지 |
| **값이 크면(높으면)** | 문서가 **여러 토픽을 골고루** (더 균일/uniform) | 토픽이 **여러 단어를 골고루** (더 균일) |
| **값이 작으면(낮으면)** | 문서가 **소수 토픽에 집중** (희소/sparse) | 토픽이 **소수 단어에 집중** (희소) |

> **기억법** 🧠 : **값이 크다 = 골고루 퍼짐(균일) / 값이 작다 = 몇 개에 집중(희소)**.
> 이 규칙은 Alpha·Beta **둘 다 똑같이** 적용됩니다.
> 예를 들어, "**낮은** Beta → 토픽이 더 균일해진다"는 서술은 **틀립니다.** 낮으면 오히려 소수 단어에 **집중**됩니다.

> ⚠️ 중요: LDA는 Dirichlet 분포가 **정수값**을 요구하기 때문에, DTM은 반드시 **단순 단어 카운트**여야 합니다.
> **TF-IDF는 LDA와 함께 쓸 수 없습니다.**
>
> 왜일까요? LDA는 문서를 **"단어를 하나하나 꺼내 담은 주머니"** 로 보고, "각 단어를 몇 번 뽑았나"를 세는 모델입니다.
> 그래서 입력값이 반드시 **셀 수 있는 개수(정수)** 여야 합니다. `3번, 1번, 0번`은 되지만,
> TF-IDF의 `0.278` 같은 **중요도 점수(소수)** 는 "0.278번 뽑았다"가 성립하지 않아 넣을 수 없습니다.

### NMF (Non-negative Matrix Factorization)

LDA보다 이해하기 쉬운 **순수 수학적 접근**입니다. 이름을 뜯어보면:

- **Non-negative Matrix** : 0 또는 양수만 있는 행렬 (DTM이 딱 여기 해당)
- **Factorization** : 하나를 둘로 쪼개기 (예: `10 = 5 × 2`)

즉 **큰 행렬(DTM)을 두 개의 작은 행렬로 분해**합니다.

$$V_{(n \times m)} \approx W_{(n \times k)} \times H_{(k \times m)}$$

- $V$ : 문서-단어 행렬 (문서 n개 × 단어 m개)
- $W$ : **문서-토픽 행렬** (문서 n개 × 토픽 k개)
- $H$ : **토픽-단어 행렬** (토픽 k개 × 단어 m개)

> **"non-negative(비음수)"가 뜻하는 것** : 다루는 모든 값이 **0 또는 양수**여야 한다는 뜻입니다(음수 금지).
> 왜냐하면 현실 데이터엔 "음수 개수"가 없기 때문이죠. 단어가 `-2번` 나올 수는 없으니까요.
> 이 제약 덕분에 결과가 **"부품(토픽)들을 더해서 만드는" 방식**이 되어 해석이 쉬워집니다.
> (예: "토픽A = 사과 0.5 + 바나나 0.3 + 포도 0.2" → 자연스럽게 "과일 토픽"으로 읽힘. 음수가 섞이면 해석이 곤란해집니다.)

> LDA와 NMF 모두 원본 DTM의 **근사치**입니다.
> 따라서 초기화나 최적화 방식에 따라 결과가 조금씩 달라질 수 있습니다.

### ⚖️ LDA vs NMF, 정면 비교

접근 방식은 다르지만 **출력물의 형태는 사실상 같다**는 점이 포인트입니다.

| 항목 | **LDA** | **NMF** |
|---|---|---|
| 정체 | **확률적·생성 모델** (Bayesian, generative) | **수학적 행렬 분해** (선형대수) |
| 핵심 도구 | 디리클레 사전분포 (α, β) | 행렬 곱 분해 ($V \approx W \times H$) |
| 사고방식 | "이 문서는 어떤 확률 과정으로 생성됐나?" | "이 행렬을 어떻게 두 조각으로 쪼갤까?" |
| 입력 제약 | **정수 카운트만** (CountVectorizer) | **비음수 값** (TF-IDF도 OK ✅) |
| 출력물 | 문서-토픽 행렬 **+** 토픽-단어 행렬 | 문서-토픽 행렬 **+** 토픽-단어 행렬 |
| 토픽 수 K | 사용자 지정 | 사용자 지정 |
| 결과 재현성 | 랜덤 초기화로 매번 달라질 수 있음 | 랜덤 초기화로 매번 달라질 수 있음 |

**한 줄 비유** 🎯
- **LDA** = "주사위를 굴려 문서를 **만들어내는** 확률 이야기" (생성 모델)
- **NMF** = "완성된 행렬을 **되돌려 쪼개는** 계산" (분해)

#### 🙋 헷갈렸던 부분

수업을 들으며 제가 실제로 헷갈렸던 두 가지입니다.

**오해 ① "문서-토픽·토픽-단어 행렬은 NMF만 만드는 거 아닌가?"**
→ **아닙니다. LDA도 똑같이 두 행렬을 만듭니다.**
NMF는 이름에 "행렬"이 있어 눈에 잘 보일 뿐이고, LDA는 그 값을 **확률**로 표현할 뿐입니다.

| | NMF | LDA |
|---|---|---|
| 문서→토픽 | "문서A는 토픽1을 **0.7만큼** 씀" (가중치) | "문서A가 토픽1일 **확률 0.7**" (확률) |
| 토픽→단어 | "토픽1은 사과를 **0.5만큼** 씀" (가중치) | "토픽1에서 사과가 나올 **확률 0.5**" (확률) |

> 즉 **가중치 vs 확률**로 부르는 이름만 다르지, 둘 다 **"문서-토픽 표"와 "토픽-단어 표"** 를 내놓습니다.
> 이 두 행렬은 **항상 세트**로 나온다고 기억하세요.

**오해 ② "NMF는 수학적 접근이니까 결과가 항상 동일한 거 아냐?"**
→ **아닙니다. NMF도 실행할 때마다 결과가 달라질 수 있습니다.** "수학적 ≠ 결정론적(항상 같은 답)"입니다.

- NMF는 `V = W × H`가 아니라 `V ≈ W × H`, 즉 **근사(approximation)** 문제입니다.
  "12를 두 수의 곱으로 쪼개라"에 `3×4`, `2×6`, `1×12` 등 여러 답이 있듯, NMF의 해도 **하나가 아닙니다.**
- 게다가 NMF는 **랜덤한 시작점에서 조금씩 개선(iteration)** 하며 답을 찾습니다.
  산 정상을 찾는데 출발 지점이 다르면 다른 봉우리에 도착하듯, **초기값에 따라 결과가 달라집니다.**
- 재현하려면 `random_state`(시드)를 **고정**해야 합니다. 이건 "시작점을 일부러 똑같이 맞춘" 것이지, NMF가 본질적으로 항상 같은 답을 주는 게 아닙니다.

> 그래서 "LDA와 NMF 모두 같은 데이터면 **항상 동일한 결과**를 보장한다"는 서술은 **틀립니다.**
> 문제의 "always(항상)"류 보기가 함정인 이유이기도 합니다.

## <span style="color:#FEB99C;">4. LDA와 클러스터링, 정확히 뭐가 다를까?</span>

수업을 들으며 가장 헷갈렸던 부분입니다. "둘 다 주제/그룹으로 나눠주는 거 아냐?"
결론부터 말하면 **"나눈다"는 표현이 함정**입니다.

> - **클러스터링** : 문서를 **분류(classify)** 한다 → *"너는 A그룹"*
> - **LDA(토픽모델링)** : 문서를 **분해(decompose)** 한다 → *"너는 A 60% + B 40%로 섞여 있어"*

### 🍕 비유: 메뉴 정리하기

식당 메뉴 100개를 정리한다고 해봅시다.

- **클러스터링 = 메뉴판 분류** : 비빔밥은 `[한식 코너]`에만 들어감. 딱 한 칸.
- **LDA = 재료 성분표** : `비빔밥 = 밥 40% + 채소 30% + 고추장 20% + 계란 10%`. 그리고 "치즈"라는 재료(토픽)는 파스타에도 피자에도 걸쳐 있음.

즉 **재료(토픽)** 는 여러 음식(문서)에 동시에 등장할 수 있습니다.

### 실제 불만 문서로 비교

> *"신용카드 대금 청구가 잘못됐고, 고객센터에 전화했더니 상담원이 불친절했어요"*

- **클러스터링의 답** : `이 문서 → 3번 클러스터` (끝)
- **LDA의 답** : `청구오류 55% + 고객서비스 40% + 기타 5%`

실제 불만글은 여러 얘기를 섞어서 하니, LDA가 더 현실적으로 보이죠. 하지만 **목적이 다릅니다.**

| 상황 | 무엇을 쓸까 |
|---|---|
| "이 불만을 **어느 팀에 배정**할까?" | **클러스터링** (한 팀에 보내야 하니 답이 하나) |
| "전체 불만 중 **어떤 이슈가 몇 %**인가?" | **LDA** (주제별 비중이 필요) |

### 출력물의 모양이 결정적으로 다르다

코드로 보면 확실합니다.

```python
# 클러스터링 → 문서마다 숫자(레이블) 하나
labels = [3, 0, 17, 3, 5, ...]

# LDA → 문서마다 토픽 확률 배열 (행 합 = 1)
doc_topics = [
    [0.55, 0.40, 0.01, 0.04, ...],   # 문서1
    [0.10, 0.05, 0.80, 0.05, ...],   # 문서2
]
```

> **클러스터링 = 숫자 1개 / LDA = 확률 배열(합 100%)** — 이 모양 차이가 두 방법의 본질입니다.

### 그럼 하드/소프트의 스펙트럼

사실 LDA와 클러스터링은 완전히 다른 세계가 아니라, **"얼마나 딱 잘라 배정하느냐"의 스펙트럼** 위에 있습니다.

```text
딱 잘라 배정 ←──────────────────────→ 확률로 섞음
  K-means      HDBSCAN      GMM        LDA
  (하드)                            (소프트/분해)
```

- **K-means** : 무조건 그룹 1개 (하드 클러스터링)
- **HDBSCAN** : 그룹 1개 또는 노이즈 (하드)
- **GMM(Gaussian Mixture)** : 여러 그룹에 확률로 걸침 (소프트)
- **LDA** : 여러 토픽에 확률로 걸침 (분해)

> 재밌게도 **소프트 클러스터링(GMM)** 까지 가면 LDA와 점점 비슷해집니다.
> 둘 다 "이 문서는 A 60%, B 40%"라고 말하니까요.
> (K-means/HDBSCAN은 2편에서 자세히 다룹니다.)

## <span style="color:#FEB99C;">5. 실습 데모: 토픽 모델링 (Demo A, sklearn)</span>

실습에서는 **CFPB(미국 소비자금융보호국) 고객 불만 데이터**로 직접 구현했습니다.
텍스트가 있는 불만만 남기고 **랜덤 1만 건**을 샘플링해 사용했습니다.

```python
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.decomposition import LatentDirichletAllocation
import numpy as np

# 전처리 + 특징 추출 (LDA는 반드시 CountVectorizer!)
vectorizer = CountVectorizer(
    token_pattern=r'\b[a-zA-Z]{3,}\b',  # 문자만, 3글자 이상
    stop_words=list(stops),              # 불용어 + Xs/날짜 패턴 추가
    ngram_range=(1, 2),                  # 유니그램 + 바이그램
    max_features=1000                    # 상위 1000개 단어만
)
dtm = vectorizer.fit_transform(complaints_df['complaint_what_happened'])

# LDA 적합
lda = LatentDirichletAllocation(
    n_components=100,          # 토픽 개수
    doc_topic_prior=25/100,    # Alpha
    topic_word_prior=0.15,     # Beta
    n_jobs=-1, random_state=123
)
doc_topics = lda.fit_transform(dtm)   # 문서-토픽 행렬 (10000 x 100)

# 토픽별 상위 단어 뽑기
vocab = np.array(vectorizer.get_feature_names_out())
def get_topic_words(topic, topic_word, vocab, top_n=10):
    top = topic_word[topic].argsort()[-top_n:][::-1]  # 상위 n개, 내림차순
    return vocab[top]
```

- **문서-토픽 행렬** : 각 행 확률 합 = 1. 임계값 0.10으로 1/0 변환 → 문서당 평균 **1.5개** 토픽
- **토픽-단어 행렬**(`lda.components_`) : `argsort()[-n:][::-1]` 로 상위 단어. 예) 토픽3 = `account, bank, funds...` → "은행 계좌 주제"
- **평가** : `lda.perplexity(dtm)` (⚠️ sklearn 구현에 오래된 버그 존재), tmtoolkit의 **U_mass**, Word Intrusion Task
- **튜닝** : `range(50, 151, 10)` 로 토픽 개수 탐색. GridSearchCV / RandomizedSearchCV 언급

> 📝 데모 과제: **NMF 직접 구현**. NMF는 비확률적이라 행 합이 1이 아니므로,
> `res / res.sum(axis=1)` 로 스케일링한 뒤 10% 임계값을 적용합니다.
> (하이퍼파라미터는 "학습을 제어하는 사람이 정하는 설정값"이며, 토픽 개수 K가 대표적입니다.)

### 결과를 효과적으로 "전달"하는 법

모델을 잘 돌리는 것만큼 **결과 소통**도 중요합니다. 효과적인 방법은:

- ✅ 코퍼스에서 **토픽 두드러짐(prominence)** 을 시각화 (어떤 토픽이 얼마나 많이 나오나)
- ✅ 각 문서의 **토픽 관련도(relevance)** 를 보여주기
- ✅ **토픽 간 유사성** 분석 (토픽들이 서로 얼마나 비슷/다른가)
- ❌ 코퍼스의 **원본 텍스트를 그대로 전부 출력** → 이건 전달이 아니라 혼란만 유발

> 핵심: 결과 전달 = **시각화하고 정리해서** 보여주기. 날것을 쏟아내는 게 아닙니다.

## <span style="color:#FEB99C;">6. 중간 정리</span>

> 토픽 모델링의 핵심은 **"문서를 하나의 그룹으로 분류하는 게 아니라, 여러 주제의 혼합으로 분해하는 것"** 입니다.

1편에서 배운 것을 정리하면:

- **비지도 학습** = 레이블 없이(X만) 데이터의 자연스러운 구조를 발견 (판단 기준: "정답이 필요한가?")
- **토픽 모델링 vs 클러스터링** = **분해(여러 주제 확률)** vs **분류(하나의 그룹)**. 사실은 하드↔소프트 **스펙트럼** 위에 있음
- **평가 지표 3종** = Perplexity(예측력, 낮을수록↓) · Coherence(응집도, 높을수록↑) · Word Intrusion(**사람**이 검증)
- **LDA** = Latent + Dirichlet + Allocation, **Alpha/Beta 사전(크면 균일·작으면 희소)**, **정수 카운트(CountVectorizer)만** 가능
- **NMF** = $V \approx W \times H$ 행렬 분해, 비확률적. **TF-IDF는 NMF에서만 사용 가능**
- **LDA·NMF 공통점** = 둘 다 **행렬 2개**(문서-토픽 + 토픽-단어) 출력, 둘 다 K 지정, 둘 다 원본의 **근사치**라 실행마다 결과가 조금씩 다름
- Demo A에서 CFPB 불만 데이터로 LDA를 적합하고, perplexity·U_mass·Word Intrusion으로 평가
