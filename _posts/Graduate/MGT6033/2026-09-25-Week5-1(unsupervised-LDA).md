## <span style="color:#FEB99C;">1. 비지도 vs 지도 학습</span>

머신러닝은 크게 **지도 학습**과 **비지도 학습**으로 나뉩니다.

| 구분 | 지도 학습(Supervised) | 비지도 학습(Unsupervised) |
|---|---|---|
| 데이터 | X(입력) + **Y(레이블)** | **X(입력)만** |
| 목적 | 레이블을 예측·분류 | 데이터의 **자연스러운 구조**를 스스로 발견 |
| 예시 | 과일 사진에 "사과/바나나" 레이블을 붙여 학습 | 특징을 보고 알아서 그룹을 형성 |

지도 학습은 사과·바나나 사진에 **정답 레이블**을 달아 "이렇게 분류해라"라고 가르치는 것이고,
비지도 학습은 레이블 없이 **"알아서 비슷한 것끼리 묶어봐"** 라고 시키는 것입니다.

> 경험칙: 가능하면 **지도 학습을 먼저 고려**하세요.
> 사람처럼 생각하도록 기계를 훈련시킬 수 있다면, 그게 거의 항상 비지도 모델보다 더 나은 결과를 냅니다.

사실 우리는 이미 비지도 학습을 접했습니다. **워드 임베딩(word2vec)** 이 대표적이죠.
모델은 `happy`와 `elated`가 "긍정적"이라는 걸 배우는 게 아니라, 단지 **비슷한 맥락에서 쓰인다**는 걸 학습합니다.
레이블을 주지 않았으니 정의상 비지도 학습입니다.

문서 수준에서 자연어에 자주 쓰이는 비지도 학습은 크게 두 가지입니다.

- **토픽 모델링** : 코퍼스 전반의 **잠재적 주제(latent topic)** 를 찾고, 각 문서에 얼마나 관련 있는지 수치화
- **클러스터링** : 문서 전체를 **하나의 그룹**으로 분류

이 둘의 차이가 이번 주 내용의 핵심이라, 6장에서 따로 자세히 다루겠습니다.

## <span style="color:#FEB99C;">2. 토픽 모델링: 문서 속 주제를 캐내기</span>

**비즈니스 시나리오**로 시작해봅시다.
당신은 갓 입사한 고객 관리 매니저이고, IT팀이 **고객 불만 10만 건**을 던져줍니다.
"이 불만들의 **공통 테마**와 각 테마의 **비중**을 일주일 안에 보고하라"는 임무를 받았습니다.

선택지는 세 가지 정도입니다.

| 방법 | 장점 | 단점 |
|---|---|---|
| 팀원에게 나눠 읽히기 | 사람이 전부 읽음 | 매우 느림, 사람마다 다르게 분류 |
| 샘플만 읽고 키워드 검색 | 덜 느림, 어느 정도 객관적 | 드문 이슈를 놓칠 수 있음, 여전히 주관적 |
| **토픽 모델링으로 자동화** | 전체 코퍼스 활용, 분석자 편향 ↓ | 완전 객관은 아님(해석 필요) |

토픽 모델링의 **핵심 단계**는 다음과 같습니다.

1. **전처리** : 숫자·구두점 제거, 표제어추출/어간추출 (품질이 여기서 갈림)
2. **특징 추출** : 텍스트를 숫자로 → Bag-of-Words(DTM) 또는 TF-IDF
3. **모델 선택** : LDA, NMF 등
4. **훈련·튜닝** : 특히 **토픽 개수**를 직접 정해야 함
5. **평가·전달** : 시각화로 결과 소통

### 토픽 품질은 어떻게 평가하나?

토픽 모델은 "잘 맞았다"를 판단하기가 애매합니다. 두 수준에서 봅니다.

- **모델 수준** : **Perplexity**(회귀의 SSE와 유사한 개념)
- **토픽 수준** : **Coherence**(단어들이 함께 등장할 확률 → PMI, U_mass 등), 그리고 사람이 하는 **Word Intrusion Task**

> Word Intrusion Task란? 한 토픽의 상위 단어 4개 + 무작위 침입 단어 1개를 섞어놓고,
> 사람에게 "안 어울리는 단어"를 고르게 합니다. 토픽이 잘 뭉쳐있다면 침입자가 **한눈에 보여야** 합니다.

## <span style="color:#FEB99C;">3. LDA & NMF: 토픽 모델링의 두 엔진</span>

### LDA (Latent Dirichlet Allocation)

가장 널리 쓰이는 토픽 모델링 기법입니다. 이름을 뜯어보면 원리가 보입니다.

| 단어 | 의미 |
|---|---|
| **Latent** | 숨겨진(잠재적인) 것 → 즉 **토픽** |
| **Dirichlet** | 베이지안 통계에서 쓰는 다변량 확률 분포 → **사전 분포(prior)** 로 사용 |
| **Allocation** | 토픽이 문서에 어떻게 **배분**되는가 |

LDA는 **생성 과정(generative process)** 을 가정합니다.
"저자가 먼저 어떤 토픽에 대해 쓸지 고르고 → 그 토픽에 맞는 단어들을 골라 문서를 쓴다"는 것이죠.

주요 하이퍼파라미터는 두 개의 Dirichlet 사전입니다.

- **Alpha (문서-토픽 사전)** : 문서 안의 토픽 분포 모양을 조절
- **Beta (토픽-단어 사전)** : 토픽 안의 단어 분포 모양을 조절

> 값이 **높으면** 더 균일한 분포, **낮으면** 희소(sparse)한 분포가 됩니다.

> ⚠️ 중요: LDA는 Dirichlet 분포가 **정수값**을 요구하기 때문에, DTM은 반드시 **단순 단어 카운트**여야 합니다.
> **TF-IDF는 LDA와 함께 쓸 수 없습니다.**

### NMF (Non-negative Matrix Factorization)

LDA보다 이해하기 쉬운 **순수 수학적 접근**입니다. 이름을 뜯어보면:

- **Non-negative Matrix** : 0 또는 양수만 있는 행렬 (DTM이 딱 여기 해당)
- **Factorization** : 하나를 둘로 쪼개기 (예: `10 = 5 × 2`)

즉 **큰 행렬(DTM)을 두 개의 작은 행렬로 분해**합니다.

$$V_{(n \times m)} \approx W_{(n \times k)} \times H_{(k \times m)}$$

- $V$ : 문서-단어 행렬 (문서 n개 × 단어 m개)
- $W$ : **문서-토픽 행렬** (문서 n개 × 토픽 k개)
- $H$ : **토픽-단어 행렬** (토픽 k개 × 단어 m개)

> LDA와 NMF 모두 원본 DTM의 **근사치**입니다.
> 따라서 초기화나 최적화 방식에 따라 결과가 조금씩 달라질 수 있습니다.

## <span style="color:#FEB99C;">4. LDA와 클러스터링, 정확히 뭐가 다를까?</span>

수업을 들으며 가장 헷갈렸던 부분입니다. "둘 다 주제/그룹으로 나눠주는 거 아냐?"
결론부터 말하면 **"나눈다"는 표현이 함정**입니다.

> - **클러스터링** : 문서를 **분류(classify)** 한다 → *"너는 A그룹"*
> - **LDA(토픽모델링)** : 문서를 **분해(decompose)** 한다 → *"너는 A 60% + B 40%로 섞여 있어"*

### 🍕 비유: 메뉴 정리하기

식당 메뉴 100개를 정리한다고 해봅시다.

- **클러스터링 = 메뉴판 분류** : 비빔밥은 `[한식 코너]`에만 들어감. 딱 한 칸.
- **LDA = 재료 성분표** : `비빔밥 = 밥 40% + 채소 30% + 고추장 20% + 계란 10%`. 그리고 "치즈"라는 재료(토픽)는 파스타에도 피자에도 걸쳐 있음.

즉 **재료(토픽)** 는 여러 음식(문서)에 동시에 등장할 수 있습니다.

### 실제 불만 문서로 비교

> *"신용카드 대금 청구가 잘못됐고, 고객센터에 전화했더니 상담원이 불친절했어요"*

- **클러스터링의 답** : `이 문서 → 3번 클러스터` (끝)
- **LDA의 답** : `청구오류 55% + 고객서비스 40% + 기타 5%`

실제 불만글은 여러 얘기를 섞어서 하니, LDA가 더 현실적으로 보이죠. 하지만 **목적이 다릅니다.**

| 상황 | 무엇을 쓸까 |
|---|---|
| "이 불만을 **어느 팀에 배정**할까?" | **클러스터링** (한 팀에 보내야 하니 답이 하나) |
| "전체 불만 중 **어떤 이슈가 몇 %**인가?" | **LDA** (주제별 비중이 필요) |

### 출력물의 모양이 결정적으로 다르다

코드로 보면 확실합니다.

```python
# 클러스터링 → 문서마다 숫자(레이블) 하나
labels = [3, 0, 17, 3, 5, ...]

# LDA → 문서마다 토픽 확률 배열 (행 합 = 1)
doc_topics = [
    [0.55, 0.40, 0.01, 0.04, ...],   # 문서1
    [0.10, 0.05, 0.80, 0.05, ...],   # 문서2
]
```

> **클러스터링 = 숫자 1개 / LDA = 확률 배열(합 100%)** — 이 모양 차이가 두 방법의 본질입니다.

### 그럼 하드/소프트의 스펙트럼

사실 LDA와 클러스터링은 완전히 다른 세계가 아니라, **"얼마나 딱 잘라 배정하느냐"의 스펙트럼** 위에 있습니다.

```text
딱 잘라 배정 ←──────────────────────→ 확률로 섞음
  K-means      HDBSCAN      GMM        LDA
  (하드)                            (소프트/분해)
```

- **K-means** : 무조건 그룹 1개 (하드 클러스터링)
- **HDBSCAN** : 그룹 1개 또는 노이즈 (하드)
- **GMM(Gaussian Mixture)** : 여러 그룹에 확률로 걸침 (소프트)
- **LDA** : 여러 토픽에 확률로 걸침 (분해)

> 재밌게도 **소프트 클러스터링(GMM)** 까지 가면 LDA와 점점 비슷해집니다.
> 둘 다 "이 문서는 A 60%, B 40%"라고 말하니까요.
> (K-means/HDBSCAN은 [2편](#)에서 자세히 다룹니다.)

## <span style="color:#FEB99C;">5. 실습 데모: 토픽 모델링 (Demo A, sklearn)</span>

실습에서는 **CFPB(미국 소비자금융보호국) 고객 불만 데이터**로 직접 구현했습니다.
텍스트가 있는 불만만 남기고 **랜덤 1만 건**을 샘플링해 사용했습니다.

```python
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.decomposition import LatentDirichletAllocation
import numpy as np

# 전처리 + 특징 추출 (LDA는 반드시 CountVectorizer!)
vectorizer = CountVectorizer(
    token_pattern=r'\b[a-zA-Z]{3,}\b',  # 문자만, 3글자 이상
    stop_words=list(stops),              # 불용어 + Xs/날짜 패턴 추가
    ngram_range=(1, 2),                  # 유니그램 + 바이그램
    max_features=1000                    # 상위 1000개 단어만
)
dtm = vectorizer.fit_transform(complaints_df['complaint_what_happened'])

# LDA 적합
lda = LatentDirichletAllocation(
    n_components=100,          # 토픽 개수
    doc_topic_prior=25/100,    # Alpha
    topic_word_prior=0.15,     # Beta
    n_jobs=-1, random_state=123
)
doc_topics = lda.fit_transform(dtm)   # 문서-토픽 행렬 (10000 x 100)

# 토픽별 상위 단어 뽑기
vocab = np.array(vectorizer.get_feature_names_out())
def get_topic_words(topic, topic_word, vocab, top_n=10):
    top = topic_word[topic].argsort()[-top_n:][::-1]  # 상위 n개, 내림차순
    return vocab[top]
```

- **문서-토픽 행렬** : 각 행 확률 합 = 1. 임계값 0.10으로 1/0 변환 → 문서당 평균 **1.5개** 토픽
- **토픽-단어 행렬**(`lda.components_`) : `argsort()[-n:][::-1]` 로 상위 단어. 예) 토픽3 = `account, bank, funds...` → "은행 계좌 주제"
- **평가** : `lda.perplexity(dtm)` (⚠️ sklearn 구현에 오래된 버그 존재), tmtoolkit의 **U_mass**, Word Intrusion Task
- **튜닝** : `range(50, 151, 10)` 로 토픽 개수 탐색. GridSearchCV / RandomizedSearchCV 언급

> 📝 데모 과제: **NMF 직접 구현**. NMF는 비확률적이라 행 합이 1이 아니므로,
> `res / res.sum(axis=1)` 로 스케일링한 뒤 10% 임계값을 적용합니다.

## <span style="color:#FEB99C;">6. 중간 정리</span>

> 토픽 모델링의 핵심은 **"문서를 하나의 그룹으로 분류하는 게 아니라, 여러 주제의 혼합으로 분해하는 것"** 입니다.

1편에서 배운 것을 정리하면:

- **비지도 학습** = 레이블 없이(X만) 데이터의 자연스러운 구조를 발견
- **토픽 모델링 vs 클러스터링** = **분해(여러 주제 확률)** vs **분류(하나의 그룹)**. 사실은 하드↔소프트 **스펙트럼** 위에 있음
- **LDA** = Latent + Dirichlet + Allocation, Alpha/Beta 사전, **정수 카운트(CountVectorizer)만** 가능
- **NMF** = $V \approx W \times H$ 행렬 분해, 비확률적. 둘 다 원본의 **근사치**
- Demo A에서 CFPB 불만 데이터로 LDA를 적합하고, perplexity·U_mass·Word Intrusion으로 평가

다음 2편에서는 **클러스터링(K-means/HDBSCAN)**, **차원의 저주**, **PCA vs UMAP** 를 이어서 다룹니다.
