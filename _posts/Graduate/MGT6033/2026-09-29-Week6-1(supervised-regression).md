Week 6에서는 **지도 학습(Supervised Learning)** 을 자연어 처리 관점에서 다뤘습니다.

지난주 비지도 학습이 **"레이블 없이 스스로 구조를 찾는"** 것이었다면,
이번주는 **"정답(레이블)을 주고 예측하도록 기계를 훈련시키는"** 세계입니다.

지도 학습은 크게 **회귀(연속형 값 예측)** 와 **분류(범주 예측)** 로 나뉩니다.
이번 1편은 **지도 학습 개요 + 훈련·튜닝·평가 + 텍스트 회귀(Lasso/SVR)** 를 다루고,
2편에서 **텍스트 분류기(의사결정나무·나이브베이즈·SGD)** 와 **앙상블(Random Forest·LightGBM)** 을 이어서 다루겠습니다.

## <span style="color:#FEB99C;">1. 지도 학습: 회귀냐 분류냐</span>

지도 학습을 가르는 기준은 딱 하나, **"예측하려는 Y(출력 변수)가 어떤 모양인가?"** 입니다.

| 유형 | 예측 대상 | Y의 모양 | 예시 |
|---|---|---|---|
| **회귀(Regression)** | 연속형 값 | 연속 분포 | 미래 매출, 주가 수익률(-100%~∞), 반품률 |
| **분류(Classification)** | 이산형 범주(레이블) | 이산(둘 이상) | 스팸 여부, 강세/약세 심리, 기업 도산, 주제 |

> 핵심 한 줄: **Y가 연속형이면 회귀, 이산형(범주)이면 분류.**
> "매출이 얼마?"는 회귀, "도산할까 말까?"는 분류입니다.

지도 학습은 강력하지만, 전통적 통계 기법(선형회귀 등)은 **복잡한 구조의 텍스트 데이터**에 잘 맞지 않는 경우가 많습니다.
그래서 머신러닝 기반 모델이 필요해집니다.

### 🔎 헷갈리기 쉬운 포인트: 지도 학습 최대의 적, "과적합(Overfitting)"

지도 학습에서 가장 중요하게 다뤄야 할 위험은 단연 **과적합**입니다.

> **과적합이란?** 모델이 **훈련 데이터는 너무 잘(심지어 완벽하게) 예측**하지만,
> **새로운 데이터(out-of-sample)에서는 성능이 뚝 떨어지는** 현상입니다.
> 훈련 데이터의 "흥미롭지 않은 잡음·미묘한 변동"까지 외워버린 것이죠.

과적합을 다루는 5가지 전략을 정리하면:

| 전략 | 하는 일 | 주의점 |
|---|---|---|
| **홀드아웃 샘플** | 훈련에서 뺀 데이터로 성능 평가 | 과적합을 *방지*하는 게 아니라 *진단*하는 도구 |
| **교차검증(CV)** | 데이터를 폴드로 나눠 번갈아 훈련·평가 | 잡음이 평균되어 사라짐. 단, **훈련 시간 대폭 증가** |
| **조기 종료** | 과적합 시작 지점에서 훈련 중단 | 모델이 지원해야 함 |
| **복잡도 축소** | 고차 비선형·무관 특성 제거 | 더 일반화되는 모델 |
| **정규화(Regularization)** | 특성이 과하면 페널티 부과 | 더 적은 파라미터, 더 작은 가중치 유도 |

> 💡 **교차검증(Cross-Validation) 한눈에**
> 5-fold CV라면? 데이터를 5조각(폴드)으로 나눠, 4조각으로 훈련하고 1조각으로 평가하기를 **5번** 반복합니다.
> 매번 평가에 쓰는 폴드를 바꿔가며(1→2→3→4→5), 그 결과를 평균 냅니다.
> 이렇게 하면 특정 데이터 조각의 특이성이 파라미터에 과하게 반영되는 걸 막아줍니다.

### 지도 학습 훈련의 5단계

모든 지도 학습 모델은 다음 단계를 거칩니다.

1. **전처리·데이터 준비** — 특성 선택, 정제, 표준화, 차원 축소 (*garbage in, garbage out*)
2. **모델 선택** — 데이터 구조에 맞는 모델 (1단계와 독립적이지 않음)
3. **훈련/홀드아웃 분할** — 보통 80:20 또는 75:25
4. **훈련** — 가능하면 교차검증 사용
5. **홀드아웃 샘플로 평가** — MSE, R² 등 + 계수 해석으로 타당성 검토

### ⚠️ 무작위 분할이 함정이 될 때: 데이터 오염(Contamination)

> 3단계(분할)는 **단순 무작위 분할이면 충분**하지 않을 때가 있습니다.

**실제 사례** 📄: 재무제표 재작성(restatement)을 예측한 논문이 있었습니다.
그런데 재작성은 **여러 해에 걸치는** 경우가 많습니다. 2016년의 문제가 2016~2018년 재무제표에 모두 영향을 주죠.
2016·2017년이 훈련 데이터에 있으면, 모델이 2018년을 "예측"하는 게 당연합니다. **사실상 홀드아웃이 오염된 것**입니다.

> 핵심: 같은 **사람·회사·산업·기간** 등으로 서로 강하게 얽힌 관측치가
> 훈련과 검증에 섞여 들어가지 않도록 조심해야 합니다.

## <span style="color:#FEB99C;">2. 훈련(Training) vs 튜닝(Tuning): 헷갈리는 두 단어</span>

우리는 흔히 훈련과 튜닝을 같은 것으로 여기지만, **하는 일이 다릅니다.**

먼저 왜 "훈련"이 필요한지부터. OLS(일반 최소제곱) 같은 고전 통계 모델은 **닫힌 형태의 해(closed-form solution)** 가 있습니다.
주어진 X, Y에 대해 답이 **딱 하나(최대우도추정)** 로 정해지죠. 선형대수와 미적분으로 바로 풀립니다.

하지만 머신러닝 모델은 **방정식보다 파라미터가 많아** 닫힌 해가 없습니다.
그래서 **경사(gradient, 관측된 미분값)** 를 이용해 **수많은 조합을 반복적으로 시도**하며 최선을 찾습니다. 이게 "학습(learning)"입니다.

### 🔑 파라미터 vs 하이퍼파라미터

| | **파라미터(Parameter)** | **하이퍼파라미터(Hyperparameter)** |
|---|---|---|
| 정체 | 데이터로부터 **학습되는** 값 | 사전에 **설정하는** 값 |
| 예시 | 회귀계수 β | k-means의 k, Lasso의 α |
| 결정 주체 | 모델(훈련이 결정) | 사람(튜닝이 결정) |

- **훈련(Training)** = 파라미터를 학습하는 과정. 지표(예: MSE)를 최소/최대화하며, 오차가 **수렴**하거나 최대 반복에 도달하면 종료.
- **튜닝(Tuning)** = 여러 하이퍼파라미터 조합을 시도해 **가장 좋은 조합을 고르는** 과정. 여기에 교차검증 같은 과적합 방지 전략이 들어감.

> 정리: **훈련은 "모델 내부의 β를 찾는 것", 튜닝은 "우리가 정하는 설정값을 고르는 것".**
> 한 번 훈련하면 최종 지표 하나(예: MSE)가 나오고, 튜닝은 그 지표를 여러 조합에 걸쳐 비교합니다.

### 평가 지표: 회귀 편

회귀형 문제는 주로 **오차 기반 점수**를 씁니다.

| 지표 | 특징 |
|---|---|
| **MSE / RMSE** | 평균제곱오차 / 그 제곱근. 모델 훈련에 직접 쓰임 |
| **MAE** | 평균절대오차. 응답 변수와 **같은 척도**라 직관적 |
| **R²** | 설명분산. 전체 적합도를 보기 좋음 |

> 💡 RMSE와 R²는 **같은 데이터를 다른 척도로** 표현한 것입니다.
> 그래서 **RMSE가 가장 좋은 모델은 R²도 가장 좋습니다.**

## <span style="color:#FEB99C;">3. 텍스트 회귀: 왜 OLS로는 부족한가</span>

OLS(일반 선형회귀)는 강력하고, 해석이 쉬우며(계수로 각 특성의 기여를 봄), 통계적 검정도 가능합니다.
분석의 **첫 번째 선택지**로 자주 쓰이죠. **하지만 NLP에는 잘 안 맞습니다.**

### OLS가 텍스트에 부적합한 5가지 이유

1. **행렬 역산 필요** — 고차원에서 부담
2. **희소성(sparsity)** — 텍스트 DTM은 0이 대부분. 단위 변화의 의미가 불분명
3. **다중공선성(multicollinearity)** — 특성들이 강하게 상관 (예: "research"와 "development"가 늘 함께) → 불안정한 계수
4. **선형만 가능** — 비선형 관계를 담기 어려움 ("profitable" vs "very profitable"의 상호작용 설정이 까다로움)
5. **특성 선택 불가** — OLS는 **모든** 특성에 계수를 부여. 무관한 단어를 제거할 메커니즘이 없음

이 한계들을 극복하는 두 가지 ML 회귀를 배웁니다: **Lasso**와 **SVR**.

### Lasso 회귀 (L1 정규화)

Lasso는 OLS 손실함수에 **L1 정규화** 페널티를 더한 것입니다.

$$\underbrace{\sum_i \left(y_i - \sum_j \beta_j x_{ij}\right)^2}_{\text{OLS 손실}} + \underbrace{\lambda \sum_j |\beta_j|}_{\text{L1 페널티}}$$

- **L1** = 계수의 **절댓값** 합 (L2는 제곱합 → 이건 Ridge 회귀)
- **λ(람다)** = 정규화 파라미터(하이퍼파라미터). 페널티 크기 조절

> **L1의 아름다움** ✨: 계수를 **정확히 0으로** 만드는 성질이 있습니다.
> 즉, 어떤 특성이 페널티를 이겨내고 살아남으려면 **정말 중요해야** 합니다.
> 결과적으로 **희소성(중요한 계수만 남김)** 을 유도하죠.

- ✅ **다중공선성 해결**: 상관된 두 특성 중 하나를 0으로, 다른 하나가 설명 담당
- ✅ **해석 가능성 유지**: 고차원에서도 개별 계수를 볼 수 있음
- ❌ **여전히 선형 모델**: 중요한 비선형성을 놓칠 수 있음

### SVR (Support Vector Regression)

SVR은 **커널 함수(kernel function)** 로 데이터에 **비선형성(곡률)** 을 도입해,
데이터를 감싸는 초평면(hyperplane)을 찾습니다.

> $f(x) \pm \epsilon$ 밴드의 중심이 적합값이 됩니다.
> 커널 함수(다항식 등)로 곡선을 만들어 데이터를 오차 밴드로 감싸면, 그에 맞춰 적합선을 그립니다.

- ✅ **비선형성 반영**: 언어는 본질적으로 비선형(단어 조합·맥락이 중요)
- ✅ **희소 데이터에 강함**: 커널이 0을 대체로 무시
- ✅ **정규화 포함**: 복잡도 완화
- ❌ **해석 어려움**: 특성 중요도를 단일 숫자로 표현 불가 (뒤에서 자세히)
- ❌ **계산 비용 높음**

### ⚖️ OLS vs Lasso vs SVR 정면 비교

| 항목 | **OLS** | **Lasso** | **SVR** |
|---|---|---|---|
| 정체 | 최대우도 선형 적합 | L1 정규화 선형 모델 | 커널 기반 비선형 모델 |
| 선형/비선형 | 선형 | 선형 | **비선형** |
| 특성 선택 | ❌ 없음 | ✅ 계수를 0으로 | 간접(정규화) |
| 다중공선성 | 취약 | ✅ 강함 | ✅ 강함 |
| 해석 가능성 | 높음 | **높음** (계수) | 낮음 (관측치별) |
| 핵심 하이퍼파라미터 | (없음) | α (페널티) | kernel, degree, gamma, C |

### 4-2. 전처리: 소셜미디어용 커스텀 토크나이저

기본 토큰화는 소셜미디어에서 **노이즈**가 많습니다. 세 가지 문제를 해결해야 합니다.

| 문제 | 해결 |
|---|---|
| 해시태그(`#`)가 분리됨 | NLTK **`TweetTokenizer`** 사용 |
| 이모지가 버려짐(단일 문자) | `emoji.is_emoji()` 로 판별해 **유지** |
| 캐시태그(`$AMZN`)의 `$`가 분리됨 | 정규표현식으로 처리 + **정규화** |

> ⭐ **캐시태그를 `cash_tag`로 정규화하는 이유**:
> 특정 종목명(`$AMZN`)이 모델의 주요 특성이 되면 안 됩니다.
> "아마존이라서 긍정적"이라는 상관관계는 원치 않죠 — **일반화 가능한 패턴**을 학습시키려는 것입니다.

```python
import re, emoji
from nltk.tokenize.casual import TweetTokenizer

tweet_tok = TweetTokenizer()
cash_tag_rx = r'\$[A-Za-z0-9.]+'   # $ + 티커 (마침표 포함 티커 허용)

def custom_tokenizer(tweet):
    tweet = re.sub(cash_tag_rx, 'cash_tag', tweet)   # $AMZN → cash_tag
    tokens = tweet_tok.tokenize(tweet)
    good = []
    for tok in tokens:
        if emoji.is_emoji(tok):                       # ① 이모지 유지
            good.append(tok)
        elif tok == 'cash_tag' or tok.startswith('#'):# ② 캐시태그·해시태그 유지
            good.append(tok.lower())
        elif len(tok) >= 3 and tok.isalpha() \
             and tok not in stopwords:                # ③ 3글자+ 알파벳 단어
            good.append(tok)
    return good
```

> 📝 정규표현식 팁: 캐시태그는 `\b`(단어 경계)로 시작할 수 없습니다 — `$`가 유효한 단어 경계가 아니라서요.

### 4-3. 특성 추출(DTM) & 훈련/테스트 분할

단순 카운트와 TF-IDF **두 버전**의 DTM을 만들었는데, 흥미롭게도 **어휘가 100% 동일**했습니다.
(`max_features=2000`이 같으니 상위 단어도 같음 → 같은 데이터를 다른 척도로 잰 것뿐). 이후엔 **TF-IDF 버전 하나만** 사용.

```python
from sklearn.model_selection import train_test_split
c_train, c_test, w_train, w_test, y_train, y_test = train_test_split(
    dtm_c, dtm_w, sentiment_score,   # 여러 데이터셋을 동시에 분할
    train_size=0.8, random_state=42  # 80/20, 재현성
)
```

> ⭐ **`train_test_split`의 아름다움**: 여러 데이터셋을 동시에 나누면서 **행(row) 정렬을 유지**합니다.
> 각각 따로 나누면 관측치가 어긋나 공정한 비교가 불가능하죠.

### 4-4. Lasso 훈련 & 핵심 교훈

먼저 기본 Lasso vs OLS(기준선)를 비교했습니다.

| 모델 | In-sample R² | In-sample MSE | **Out-of-sample MSE** |
|---|---|---|---|
| OLS | ~64% | ~0.09 | **0.17** (2배 ↑) |
| Lasso (α=0.1) | ~0 | 0.26 | ~0.26 |

여기서 **두 가지 결정적 교훈**이 나옵니다.

> ⭐ **교훈 1: In-sample에선 OLS가 항상 최고입니다.**
> OLS는 선형 모델의 **최대우도추정(정의상 최선의 선형 적합)** 이라, 선형에 갇힌 어떤 ML도 이를 못 이깁니다.
>
> ⭐ **교훈 2: 그래서 In-sample로 비교하면 안 됩니다.**
> OLS의 MSE가 0.09→0.17로 **2배** 뛴 것 = **과적합**의 증거. 반드시 **out-of-sample로 평가**해야 합니다.
> (Lasso의 R²=0은 α가 너무 커서 모든 계수가 0이 된 **과도한 정규화** 상태)

### 4-5. Lasso 튜닝: `GridSearchCV`

α를 제대로 찾기 위해 그리드 서치를 돌립니다.

```python
from sklearn.model_selection import GridSearchCV
alphas = np.arange(...)[::2]                   # 5,000개 α 값
params = {'alpha': alphas, 'random_state': [42]}

gs = GridSearchCV(
    Lasso(), params,
    scoring=['neg_root_mean_squared_error', 'r2'],  # 2개 지표
    cv=3, n_jobs=-1, refit=False               # 3-fold CV, 병렬화
)
gs.fit(w_train, y_train)                        # 5,000 × 3 = 15,000회 적합
```

- **`neg_root_mean_squared_error`**: MSE에 음수 부호를 붙여, 최소화 대신 **최대화** 문제로 통일 (grid search 관례)
- 지표가 2개면 무엇을 최적화할지 모르므로 **`refit=False`**
- 결과: 최적 α ≈ **9e-05** → 재적합하니 **out-of-sample에서 Lasso가 OLS를 소폭 능가** ✅

### 4-6. Lasso 계수 해석 (최대 강점)

- **2,000개 중 1,457개 계수가 정확히 0** → 약 **73%의 특성이 제거됨** (희소성!). (OLS는 0개)
- **상위 예측 단어**:
  - 음(-): `disposed`(처분), `bearish`(약세), `short`(공매도) → 감성 하락
  - 양(+): `purchases`(매수) 등 → 감성 상승 (직관과 일치!)
- 🔎 **발견**: 이모지가 상위에 없음 → StockTwits의 NLP는 이모지를 안 쓰는 듯 (2편에서 대조됨)

### 4-7. SVR 훈련 & 튜닝

기본 SVR을 돌리니 **심각한 과적합**이 나타났습니다.

| 모델 | In-sample MSE | Out-of-sample MSE |
|---|---|---|
| SVR (기본) | **0.03** | **0.15** (약 5배 ↑) |
| Lasso (최적) | ~0.12 | 0.14 |
| OLS | ~0.09 | 0.17 |

> ⭐ **교훈 3: 모델이 복잡할수록(비선형↑) 과적합 위험이 커집니다.**
> SVR은 in-sample에선 압도적(0.03)이지만, out-of-sample에서 5배로 폭증했습니다.

SVR 튜닝은 **`RandomizedSearchCV`** 로 (연속형 파라미터에 효율적):

```python
from sklearn.model_selection import RandomizedSearchCV
from scipy.stats import uniform   # .rvs()로 난수 생성 가능한 분포 객체

param_grid = {
    'kernel': ['poly', 'rbf', 'sigmoid'],
    'degree': [2, 3, 4, 5],                    # poly에만 적용
    'gamma':  uniform(loc=0.0005, scale=0.10), # 커널 계수(비선형 형태)
    'C':      uniform(loc=0.1, scale=1.25)     # 정규화 파라미터
}
rs = RandomizedSearchCV(SVR(), param_grid,
        scoring='neg_root_mean_squared_error', cv=3, n_jobs=-1)
```

- ⭐ **교차검증이 과적합을 크게 해소**: 3-fold CV만으로도 in-sample MSE가 더 이상 0.03이 아님
- **최종 순위 (out-of-sample)**: **Lasso(최고) > SVR > OLS**. 최적 커널 = **RBF**
- → 💡 **항상 복잡한 모델이 이기는 건 아닙니다.** 이 데이터에선 Lasso가 최선이었습니다.

### 🙋 헷갈렸던 부분: 비선형 모델의 "특성 중요도"

> **오해: "SVR도 Lasso처럼 어떤 단어가 중요한지 계수로 볼 수 있지 않나?"**
> → **아닙니다. 비선형 모델은 계수로 볼 수 없습니다.**

미적분으로 보면, 특성 중요도는 $\partial(\text{sentiment}) / \partial(\text{short})$ 입니다.
**선형 모델**에선 이 미분값이 **상수(계수)** 라 딱 하나의 숫자죠. 하지만 **비선형 모델**에선:

1. **곡선 위 위치에 따라** 미분값이 달라짐
2. **상호작용 효과** — "short"의 효과가 다른 단어("sell" 등) 존재 여부에 의존

> 그래서 SVR·비선형 모델의 중요도는 **관측치별(observation-specific)** 입니다.
> 요약하려면 **SHAP(Shapley) 값**이나 **순열 중요도(Permutation Importance)** 를 씁니다. (수업 범위 밖, 검색 권장)

## <span style="color:#FEB99C;">5. 중간 정리</span>

> 회귀 파트의 핵심은 **"과적합을 진단하고(홀드아웃), 정규화·교차검증으로 다스리며, 반드시 out-of-sample로 평가하는 것"** 입니다.

1편에서 배운 것을 정리하면:

- **지도 학습** = X + **Y(레이블)** 로 예측. **Y가 연속형이면 회귀, 이산형이면 분류**
- **과적합** = 훈련만 잘하고 새 데이터엔 약함. **홀드아웃·CV·조기종료·복잡도↓·정규화**로 대응
- **훈련 vs 튜닝** = 파라미터(β) 학습 vs 하이퍼파라미터(α 등) 선택
- **회귀 평가** = MSE·RMSE·MAE·R² (RMSE 최고 = R² 최고)
- **OLS는 NLP에 부적합** (희소·다중공선성·선형·특성선택 불가) → **Lasso**(L1, 계수를 0으로, 해석 가능) / **SVR**(커널로 비선형, 해석 어려움)
- **핵심 도구** = `ftfy`(인코딩) · `TweetTokenizer`(소셜 토큰화) · `train_test_split`(행 정렬) · `GridSearchCV`/`RandomizedSearchCV`(튜닝)
- **In-sample 비교는 금물** — OLS·SVR은 항상 좋아 보임. **복잡한 모델이 항상 최선은 아님**

다음 2편에서는 **텍스트 분류기(의사결정나무·나이브베이즈·SGD)**, **앙상블(Random Forest·LightGBM)**, 그리고 **클래스 불균형과 커스텀 비용함수** 를 이어서 다룹니다.
