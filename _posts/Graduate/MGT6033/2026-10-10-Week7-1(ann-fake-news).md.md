## <span style="color:#FEB99C;">1. 인공신경망: 가중합과 변환을 여러 층으로 쌓는다</span>

인공신경망은 생물학적 신경망에서 아이디어를 얻었지만,
계산 자체는 생각보다 단순합니다.

> **입력을 가중합으로 묶고 → 변환하고 → 다음 층으로 전달하기.**
> 그리고 예측이 틀리면, 그 연결의 강도인 **가중치(weight)** 를 수정합니다.

### 1-1. 입력층·은닉층·출력층

| 구성 | 하는 일 | 크기를 정하는 기준 |
|---|---|---|
| **입력층(Input layer)** | 데이터를 받음 | 입력 특성 수 |
| **은닉층(Hidden layers)** | 입력을 조합하고 변환 | 설계자가 정하는 하이퍼파라미터 |
| **출력층(Output layer)** | 최종 예측을 생성 | 예측 대상과 문제 유형 |

예를 들어 문서-단어 행렬(DTM)에 특성이 1,000개 있다면,
기본적인 Dense 신경망은 **문서당 1,000개의 숫자**를 입력으로 받습니다.

은닉층을 몇 개 둘지, 각 층에 노드를 몇 개 둘지는 우리가 정합니다.

- 은닉층 2개, 각 10개 노드
- 은닉층 3개, 각각 64·32·16개 노드
- 더 깊고 넓은 구조

모두 가능하지만, **크게 만들수록 더 좋은 것은 아닙니다.**

> 💡 **강의의 설계 원칙: 작게 시작하고, 필요하면 확장하기.**
> 층과 노드가 많아지면 표현력뿐 아니라 파라미터 수·훈련 비용·과적합 위험도 함께 증가합니다.

### 1-2. 뉴런 하나에서는 무슨 일이 일어날까?

입력값이 $x_1, x_2, x_3$라면, 한 뉴런은 먼저 다음 값을 계산합니다.

$$
z = w_1x_1 + w_2x_2 + w_3x_3 + b
$$

그다음 활성화 함수 $g$를 적용합니다.

$$
a = g(z)
$$

- **$w$**: 입력이 얼마나 중요한지 결정하는 가중치
- **$b$**: 전체 입력을 이동시키는 편향항
- **$g$**: 비선형 변환 등을 담당하는 활성화 함수
- **$a$**: 다음 층으로 전달되는 출력

> 🙋 **헷갈리기 쉬운 포인트: 여기서 bias는 ‘차별적 편향’이 아닙니다.**
>
> 신경망 식의 **bias $b$** 는 회귀식의 절편과 비슷한 **학습 파라미터**입니다.
> 반면 데이터 편향이나 다수 클래스 편향은 **데이터·예측 성향의 문제**입니다.
> 같은 단어지만 문맥이 다릅니다.

### 1-3. 파라미터는 몇 개일까?

Dense 층은 이전 층의 모든 노드와 연결됩니다.

입력 노드가 $m$개, 출력 노드가 $n$개라면:

$$
\text{파라미터 수} = mn+n = (m+1)n
$$

뒤의 $n$은 각 출력 노드에 하나씩 붙는 **bias**입니다.

강의의 작은 예제는 다음 구조였습니다.

```text
입력 3개 → 은닉 2개 → 은닉 4개 → 은닉 3개 → 출력 1개
```

| 연결 | 계산 | 파라미터 |
|---|---:|---:|
| 입력 3 → 은닉 2 | 3×2 + 2 | 8 |
| 은닉 2 → 은닉 4 | 2×4 + 4 | 12 |
| 은닉 4 → 은닉 3 | 4×3 + 3 | 15 |
| 은닉 3 → 출력 1 | 3×1 + 1 | 4 |
| **합계** | | **39** |

> 핵심: **학습한다는 것은 이 가중치와 bias의 값을 데이터에 맞춰 조정한다는 뜻**입니다.

## <span style="color:#FEB99C;">2. 활성화 함수: 신경망을 비선형으로 만드는 핵심</span>

이번 주 가장 중요한 개념 중 하나가 **활성화 함수(Activation function)** 입니다.

### ⚠️ 층을 많이 쌓기만 하면 비선형 모델이 될까?

**아닙니다.**

비선형 활성화 없이 선형·아핀 변환만 쌓으면,
결국 하나의 선형·아핀 변환으로 합쳐집니다.

$$
h = W_1x+b_1
$$

$$
y = W_2h+b_2
  = W_2W_1x + W_2b_1+b_2
$$

즉:

$$
y = W^\ast x+b^\ast
$$

> ⭐ **층의 개수 자체가 비선형성을 보장하지 않습니다.**
> 일반적인 Dense 신경망이 복잡한 비선형 관계를 학습하는 핵심은
> **층 사이에 들어가는 비선형 활성화 함수**입니다.

### 2-1. 자주 쓰는 활성화 함수

| 함수 | 형태 | 주로 쓰는 곳 |
|---|---|---|
| **Linear** | $g(z)=z$ | 일반적인 연속형 회귀 출력 |
| **ReLU** | $g(z)=\max(0,z)$ | 은닉층 |
| **Sigmoid** | $g(z)=1/(1+e^{-z})$ | 이진 분류의 단일 출력 |
| **Softmax** | 여러 점수를 합이 1인 확률로 변환 | 상호 배타적 다중 클래스 분류 |

#### ReLU: 음수는 0, 양수는 그대로

$$
\operatorname{ReLU}(z)=\max(0,z)
$$

규칙은 간단하지만, 0을 기준으로 작동 방식이 달라지므로 **비선형 함수**입니다.
여러 ReLU 뉴런을 조합하면 복잡한 구간별 관계를 표현할 수 있습니다.

#### Sigmoid: 하나의 점수를 0~1로

$$
\sigma(z)=\frac{1}{1+e^{-z}}
$$

- 매우 큰 양수 → 1에 가까움
- 0 → 0.5
- 매우 큰 음수 → 0에 가까움

가짜 뉴스가 1, 진짜 뉴스가 0이라면,
출력을 **가짜 뉴스 클래스에 대한 예측 확률**로 해석하도록 학습할 수 있습니다.

단, 이 값이 실제 정답률과 일치하는지는 별도의 **확률 보정(calibration)** 문제입니다.

#### Softmax: 여러 클래스 중 하나를 선택

$$
p_k=\frac{e^{z_k}}{\sum_j e^{z_j}}
$$

긍정·중립·부정처럼 **정확히 하나만 정답인 문제**에서,
각 클래스의 확률을 계산합니다. 모든 확률의 합은 1입니다.

### 🔎 이진 분류·다중 클래스·다중 레이블을 구분하자

| 문제 | 정답의 형태 | 대표적인 출력 설정 |
|---|---|---|
| **이진 분류** | 가짜 / 진짜 | Sigmoid 1개 |
| **다중 클래스** | 긍정 / 중립 / 부정 중 하나 | 클래스 수만큼 Softmax |
| **다중 레이블** | 한 문서에 금융·환경·노동 주제 동시 존재 | 레이블별 Sigmoid |

> 💡 **다중 클래스는 “하나를 고르는 것”, 다중 레이블은 “여러 개가 동시에 맞을 수 있는 것”.**
>
> 참고로 이진 분류도 출력 2개와 Softmax로 구현할 수 있습니다.
> 또한 logits를 직접 받는 손실함수를 쓰면 출력층에 Sigmoid를 명시하지 않을 수도 있습니다.
> 중요한 것은 **출력 형태와 손실함수의 조합이 맞는지**입니다.

## <span style="color:#FEB99C;">3. 신경망은 어떻게 학습할까? Forward → Loss → Backpropagation</span>

신경망 학습은 다음 과정을 반복합니다.

1. **초기화**: 가중치의 시작값을 설정
2. **순전파(Forward pass)**: 입력으로 예측 생성
3. **손실 계산**: 정답과 예측이 얼마나 다른지 측정
4. **역전파(Backpropagation)**: 각 파라미터가 손실에 미치는 기울기 계산
5. **업데이트**: optimizer가 기울기를 사용해 파라미터 수정

### 3-1. 역전파와 optimizer는 같은 것일까?

아닙니다. 역할이 다릅니다.

| 개념 | 역할 |
|---|---|
| **손실함수(Loss)** | 무엇을 줄여야 하는가? |
| **역전파(Backpropagation)** | 각 파라미터를 바꾸면 손실이 어떻게 달라지는가? |
| **Optimizer** | 계산된 기울기로 실제 업데이트를 어떻게 할 것인가? |
| **학습률(Learning rate)** | 한 번에 얼마나 움직일 것인가? |

단순 경사하강법은 다음처럼 표현됩니다.

$$
\theta_{t+1}
=
\theta_t-\eta\nabla_\theta L
$$

- $\theta$: 가중치와 bias를 포함한 파라미터
- $\eta$: 학습률
- $\nabla_\theta L$: 손실의 기울기

강의에서는 **Adam**을 사용했습니다.
Adam은 기울기의 이동평균 등을 이용해 파라미터별 업데이트 크기를 조절하는 optimizer입니다.

> 🙋 **“학습률이 작으면 무조건 좋은가?”**
>
> 너무 크면 학습이 불안정해질 수 있고,
> 너무 작으면 학습이 느리거나 제한된 시간 안에 충분히 개선되지 않을 수 있습니다.
> **작은 학습률이 전역 최적해를 보장하는 것도 아닙니다.**

### 3-2. Epoch·Batch·Step의 차이

| 용어 | 의미 |
|---|---|
| **Epoch** | 훈련 데이터 전체를 한 번 처리 |
| **Batch size** | 한 번에 처리하는 관측치 수 |
| **Training step** | 일반적인 설정에서 한 배치를 처리하고 업데이트하는 단위 |

강의의 합성 데이터 실습에서는:

- 전체 관측치: **10,000개**
- 훈련 관측치: **8,000개**
- Batch size: **32**

따라서:

$$
\text{1 epoch의 batch 수}=\frac{8,000}{32}=250
$$

20 epochs라면 기본 설정에서:

$$
250\times20=5,000\text{번의 업데이트}
$$

> 💡 화면의 `250/250`은 “250 epochs”가 아니라,
> **현재 epoch 안의 배치 처리가 끝났다는 뜻**입니다.
>
> 다만 gradient accumulation 같은 추가 설정을 쓰면
> 배치 처리 횟수와 optimizer 업데이트 횟수가 달라질 수 있습니다.

### 3-3. 손실함수와 평가 지표도 구분하자

| 문제 | 대표적인 손실함수 | 함께 볼 평가 지표 |
|---|---|---|
| 회귀 | MSE | RMSE, MAE, R² |
| 이진 분류 | Binary cross-entropy | Accuracy, Precision, Recall, F1 |
| 다중 클래스 | Categorical / Sparse categorical cross-entropy | Accuracy, Macro-F1 |

이진 분류의 Binary cross-entropy는:

$$
L=-\frac{1}{N}\sum_i
\left[
y_i\log p_i+(1-y_i)\log(1-p_i)
\right]
$$

> ⭐ **정확도와 손실은 같은 정보가 아닙니다.**
>
> 정답이 1인 사례에 0.51과 0.99를 예측하면,
> 임계값 0.5 기준으로는 둘 다 정답입니다.
> 하지만 cross-entropy는 두 예측을 다르게 평가합니다.

MSE도 0/1 정답과 예측 확률 사이에서 계산할 수 있습니다.
다만 일반적인 분류 신경망에서는 **확률 모형과 잘 맞는 cross-entropy를 주로 사용**합니다.

## <span style="color:#FEB99C;">4. Keras 실습: 만들고 → Compile하고 → Fit하기</span>

강의에서는 **TensorFlow의 Keras API**로 신경망을 구성했습니다.

- **TensorFlow**: 텐서 연산과 자동 미분 등을 담당하는 프레임워크
- **Keras**: 신경망 구성·훈련을 편리하게 해 주는 고수준 API

아래 코드는 강의의 39개 파라미터 구조에 ReLU를 추가한 버전입니다.

```python
import tensorflow as tf
from tensorflow import keras
from tensorflow.keras import layers

tf.keras.utils.set_random_seed(42)

model = keras.Sequential([
    keras.Input(shape=(3,)),
    layers.Dense(2, activation="relu"),
    layers.Dense(4, activation="relu"),
    layers.Dense(3, activation="relu"),
    layers.Dense(1)
])

model.summary()

model.compile(
    optimizer="adam",
    loss="mse"
)
```

### 왜 `compile()`이 따로 필요할까?

신경망의 **구조**와 **학습 방법**이 별개이기 때문입니다.

- `Sequential`, `Dense`: 어떤 계산 구조를 만들 것인가?
- `compile`: 어떤 optimizer와 loss로 학습할 것인가?
- `fit`: 실제 데이터로 가중치를 학습

### 4-1. 합성 데이터로 비선형 학습 확인하기

강의에서는 세 종류의 입력 변수를 생성했습니다.

- 정규분포에서 나온 변수
- 0/1 형태의 이진 변수
- 이동시킨 지수분포 변수

그리고 이들을 **제곱항·로그·비율·상호작용**으로 조합해 연속형 정답을 만들었습니다.

의도는 분명합니다.

> **“우리가 복잡한 식으로 만든 관계를, 신경망이 데이터만 보고 근사할 수 있을까?”**

강의 실행에서는 선형 활성화만 사용한 모델의 손실이 약 132~133 수준에서 정체했습니다.
이후 ReLU와 더 긴 훈련·조기 종료를 적용한 실험에서는 검증 손실이 약 9.6까지 내려갔습니다.

단, **활성화뿐 아니라 훈련 설정도 바뀐 실험**이므로,
이 차이 전체를 ReLU 하나의 효과로 해석해서는 안 됩니다.

### 4-2. Callback과 Early Stopping

**Callback**은 학습 도중 특정 시점에 실행되는 보조 기능입니다.

| Callback의 역할 | 예시 |
|---|---|
| 학습 중단 | 성능이 개선되지 않으면 종료 |
| 모델 저장 | 가장 좋은 모델을 체크포인트로 보관 |
| 학습률 조정 | 성능 정체 시 학습률 감소 |
| 기록 | 지표·훈련 과정을 저장 |

가장 중요한 것은 **조기 종료(Early stopping)** 입니다.

```python
early_stop = keras.callbacks.EarlyStopping(
    monitor="val_loss",
    mode="min",
    patience=5,
    restore_best_weights=True
)

# X_train, y_train: 훈련 데이터
# X_val, y_val: 조기 종료 판단용 검증 데이터
history = model.fit(
    X_train,
    y_train,
    validation_data=(X_val, y_val),
    epochs=200,
    batch_size=32,
    callbacks=[early_stop]
)
```

- **`monitor="val_loss"`**: 검증 손실을 관찰
- **`patience=5`**: 최적값 갱신 없이 5 epochs가 지나면 종료
- **`restore_best_weights=True`**: 종료 시점이 아니라 가장 좋았던 시점의 가중치로 복원

강의에서는 약 45번째 epoch에서 검증 손실이 가장 낮았고,
이후 5 epochs 동안 개선되지 않아 약 50번째 epoch에서 멈췄습니다.

> ⚠️ **학습을 멈추는 것과 최적 모델로 돌아가는 것은 별개입니다.**
> 최적 가중치 복원이나 체크포인트 로드를 설정하지 않으면,
> 마지막 시점의 가중치가 남을 수 있습니다.

### 🔎 같은 모델에 `fit()`을 다시 호출하면?

일반적으로 **기존에 학습한 가중치에서 이어서 학습**합니다.

처음부터 다른 구조나 설정을 비교하려면 모델을 새로 만들어야 합니다.

또한 초기화·데이터 순서·하드웨어 연산 때문에 결과가 달라질 수 있으므로,
재현성을 위해 seed를 설정하고 필요하면 여러 번 실행한 변동성도 확인합니다.

> 좋은 결과가 나올 때까지 반복하고 최고값만 보고하는 것은
> 재현성 확보가 아니라 **선택 편향**에 가깝습니다.

## <span style="color:#FEB99C;">5. NLP 신경망 설계: 무엇을 입력으로 줄 것인가?</span>

신경망은 텍스트 문자열 자체가 아니라 **숫자로 표현된 입력**을 처리합니다.

| 표현 방식 | 장점 | 한계 |
|---|---|---|
| **Count DTM / TF-IDF** | 간단하고 빠름 | 전체 단어 순서·문맥을 직접 보존하지 못함 |
| **Word2Vec / GloVe** | 단어 간 의미 관계를 표현 | 기본적인 정적 임베딩은 문맥에 따라 단어 표현이 달라지지 않음 |
| **문맥 임베딩** | 같은 단어도 문맥에 따라 다른 표현 | 더 큰 계산 비용 |

### 5-1. 분석 단위도 모델 설계다

- 문서 전체를 분류할 것인가?
- 문단 단위로 나눌 것인가?
- 문장마다 레이블을 붙일 것인가?

이는 단순한 전처리 선택이 아닙니다.

예를 들어 한 투자 보고서 안에도:

- 기업 실적 설명
- 경영진 평가
- 투자 의견
- 산업 전망

이 섞여 있을 수 있습니다.

> 💡 **문서 전체에 하나의 레이블을 붙이는 문제와,
> 문장별로 재무 내용을 찾는 문제는 서로 다른 과제**입니다.

### 5-2. 순서·길이·계산 비용

강의는 RNN·LSTM·GRU처럼 순서를 처리하는 구조와,
전역적인 토큰 관계를 다루는 Transformer도 소개합니다.

다만 구조가 복잡해지면:

- 더 많은 파라미터
- 더 큰 메모리 사용량
- 더 긴 훈련 시간
- 더 큰 과적합 위험

이 따라옵니다.

대응 방법은 **작은 구조부터 시작하기, Dropout, Weight decay, 조기 종료, 전이학습** 등입니다.

> 🙋 **Normalization과 Regularization은 다릅니다.**
>
> - **Normalization**: 입력의 크기나 척도를 조절
> - **Regularization**: 모델의 과도한 적합을 억제
>
> 둘 다 한국어로 ‘정규화’라고 부르는 경우가 있어 혼동하기 쉽습니다.

## <span style="color:#FEB99C;">6. 가짜 뉴스 분류: 데이터 준비와 ANN 설계</span>

본격적인 실습에서는 약 **45,000개 뉴스 기사**를 사용했습니다.

- **가짜 뉴스: 1**
- **진짜 뉴스: 0**
- 비율은 대략 **가짜 52%, 진짜 48%**

지난주 StockTwits처럼 극단적인 클래스 불균형은 아닙니다.

### 6-1. 모델을 만들기 전에 출처 단서를 확인하기

진짜 뉴스에는 다음과 같은 문구가 자주 등장했습니다.

```text
WASHINGTON (Reuters) ...
```

이 상태로 학습하면 모델은 무엇을 배울까요?

> **“내용이 사실인가?”가 아니라 “Reuters라는 단어가 있는가?”를 배울 수 있습니다.**

강의에서는 문장 시작의 **도시명 + Reuters**를 정규표현식으로 제거했습니다.

```python
import re

source_prefix = re.compile(
    r"^[A-Z\s/]+\s*\(Reuters\)\s*[-–—]?\s*"
)

def clean_text(text):
    return source_prefix.sub("", str(text))
```

이 정규식은 강의에서 관찰한 형태를 처리하는 예시입니다.
모든 지역명·문장 형식·기사 출처를 완벽하게 제거하지는 못합니다.

> ⚠️ **출처를 한 번 지웠다고 출처 관련 편향이 사라지는 것은 아닙니다.**
> 본문의 매체명, 문체, 인용 방식, 특정 주제가 여전히 출처의 대리변수가 될 수 있습니다.

### 6-2. 레이블 변환과 DTM

```python
news["clean_text"] = news["text"].map(clean_text)
news["y"] = news["label"].map({"fake": 1, "true": 0})
```

강의의 특성 설정은 다음과 같습니다.

| 설정 | 값 |
|---|---|
| 최대 특성 수 | 1,000 |
| 불용어 | 영어 불용어 |
| 토큰 | 알파벳 3글자 이상 |
| N-gram | Unigram + Bigram |
| 입력 크기 조절 | 문서 벡터의 L2 normalization |

L2 normalization은 각 문서 벡터를 다음처럼 바꿉니다.

$$
\tilde{x}_i=\frac{x_i}{\|x_i\|_2}
$$

0이 아닌 벡터의 길이가 1이 되므로,
기사 길이 때문에 전체 단어 빈도가 커지는 효과를 완화합니다.

단, 이것이 **문서 길이와 연관된 모든 정보를 완전히 제거한다는 뜻은 아닙니다.**

### 6-3. 보완한 구현: 분할 먼저, 어휘 학습은 훈련 데이터에서만

강의 흐름을 실제 프로젝트에 옮길 때는,
전체 데이터에서 어휘를 먼저 만들기보다 **분할 후 훈련 데이터에만 vectorizer를 fit**하는 편이 안전합니다.

```python
from sklearn.model_selection import train_test_split
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.preprocessing import normalize

train_text, val_text, y_train, y_val = train_test_split(
    news["clean_text"],
    news["y"],
    test_size=0.2,
    random_state=42,
    stratify=news["y"]
)

vectorizer = CountVectorizer(
    max_features=1000,
    stop_words="english",
    token_pattern=r"(?u)\b[a-zA-Z]{3,}\b",
    ngram_range=(1, 2)
)

X_train_sparse = vectorizer.fit_transform(train_text)
X_val_sparse = vectorizer.transform(val_text)

X_train = normalize(X_train_sparse).toarray().astype("float32")
X_val = normalize(X_val_sparse).toarray().astype("float32")
```

> 📝 여기서 `val`은 **조기 종료와 설정 선택에 사용하는 검증 데이터**입니다.
> 최종 성능을 엄격하게 보고하려면 별도의 테스트셋을 남겨 두어야 합니다.
>
> 같은 기사·사건·출처가 여러 행에 걸쳐 반복된다면,
> 단순 무작위 분할 대신 그룹·시간·출처 기반 분할도 고려해야 합니다.

### ⚠️ 희소 행렬을 Dense로 바꿀 때의 메모리

강의의 구현에서는 입력을 Dense 배열로 변환했습니다.
하지만 “Keras는 희소 입력을 절대로 처리하지 못한다”는 일반화는 정확하지 않습니다.
지원 여부는 입력 경로·층·버전에 따라 달라집니다.

중요한 것은 `.toarray()`의 비용입니다.

45,000행 × 1,000열이라면 약 4,500만 개의 값입니다.

- float32 기준: 약 **180MB**
- float64 기준: 약 **360MB**

여기에 복사본과 학습용 메모리가 추가됩니다.

### 6-4. 네트워크: 1,000 → 10 → 10 → 1

강의에서는 비교적 작은 구조를 사용했습니다.

```python
classifier = keras.Sequential([
    keras.Input(shape=(X_train.shape[1],)),
    layers.Dense(10, activation="relu"),
    layers.Dense(10, activation="relu"),
    layers.Dense(1, activation="sigmoid")
])

classifier.compile(
    optimizer="adam",
    loss="binary_crossentropy",
    metrics=["accuracy"]
)

early_stop = keras.callbacks.EarlyStopping(
    monitor="val_accuracy",
    mode="max",
    patience=5,
    restore_best_weights=True
)

history = classifier.fit(
    X_train,
    y_train,
    validation_data=(X_val, y_val),
    epochs=50,
    batch_size=32,
    callbacks=[early_stop]
)
```

입력이 정확히 1,000개라면 파라미터는:

$$
(1000+1)\times10
+
(10+1)\times10
+
(10+1)\times1
=
10,131
$$

은닉층은 작지만, 첫 번째 층에만 이미 **10,010개**가 있습니다.

> 💡 **파라미터 수는 층의 깊이뿐 아니라 입력 차원에 크게 좌우됩니다.**

## <span style="color:#FEB99C;">7. 정확도 98%: 축하하기 전에 확인할 것</span>

강의 실행에서는 첫 epoch부터 검증 정확도가 약 **97.8%**였고,
약 5번째 epoch에서 **98.24%** 정도까지 올라갔습니다.

매우 빠르고 높은 성능입니다.

그런데 강의의 반응은 단순히 “좋은 모델이네요”가 아니었습니다.

> **“이렇게 잘되면, 먼저 내가 실수하지 않았는지 확인해야 한다.”**

### 7-1. 고성능 모델 감사 체크리스트

| 질문 | 확인할 위험 |
|---|---|
| 정답이나 정답의 변형이 입력에 들어갔나? | Target leakage |
| 훈련·검증에 중복 기사가 섞였나? | 데이터 중복·오염 |
| 기사 출처만으로 구분되나? | 출처 단서 |
| 문서 길이가 크게 다른가? | 규모 차이 |
| 특정 주제·인물만으로 나뉘나? | 주제 편향 |
| 다른 출처·시점에서도 유지되나? | 일반화 실패 |

정답과 직접 연결된 정보가 입력에 들어가는 **누수**와,
데이터셋에서는 잘 통하지만 현실에서는 약한 **지름길 학습(shortcut learning)** 은 구분할 필요가 있습니다.

둘 다 높은 검증 점수를 실제 능력으로 오해하게 만들 수 있습니다.

### 7-2. 확률을 레이블로 바꾸고 클래스별 평가하기

```python
import numpy as np
from sklearn.metrics import classification_report

p_fake = classifier.predict(X_val, verbose=0).ravel()
pred_fake = (p_fake > 0.5).astype(int)

print(
    classification_report(
        y_val,
        pred_fake,
        target_names=["true", "fake"],
        zero_division=0
    )
)
```

- `predict()`의 출력: `(관측치 수, 1)`
- `ravel()` 또는 `flatten()`: 1차원 배열로 변환
- 임계값 0.5: 확률을 0/1 레이블로 변환

강의에서는 전체 데이터에 예측을 붙여 **273개의 오분류 사례**도 확인했습니다.

> ⚠️ **전체 데이터에는 훈련 데이터가 포함됩니다.**
> 따라서 이 오분류 건수는 오류 분석용이지,
> 독립적인 테스트 성능으로 보고할 숫자는 아닙니다.

### 7-3. 어떤 단어가 다른가?

강의에서는 클래스별 평균 특성값을 비교했습니다.

$$
\Delta_j
=
\operatorname{Mean}(x_j\mid fake)
-
\operatorname{Mean}(x_j\mid true)
$$

- $\Delta_j>0$: 가짜 뉴스에서 상대적으로 큰 특성
- $\Delta_j<0$: 진짜 뉴스에서 상대적으로 큰 특성

관찰된 경향은 다음과 같습니다.

| 진짜 뉴스 쪽 | 가짜 뉴스 쪽 |
|---|---|
| `said` 등 인용 관련 표현 | 더 일상적·구어적인 표현 |
| 요일·공식 직함 등 구체적 표현 | Twitter·이미지 관련 표현 |
| 비교적 공식적인 문체 | 특정 정치 인물·주제 관련 표현 |

또한 `Reuters`가 여전히 나타나,
전처리가 출처 단서를 완전히 제거하지는 못했음을 보여 주었습니다.

> ⭐ **클래스별 단어 평균 차이는 모델의 특성 중요도와 같지 않습니다.**
> 데이터가 어떻게 다른지 보여 주는 탐색 분석이지,
> 그 단어가 예측에 인과적으로 기여했다는 증거는 아닙니다.

### 7-4. Permutation Importance는 무엇인가?

학습된 모델을 고정한 상태에서:

1. 기준 성능을 계산
2. 특정 특성 열만 무작위로 섞음
3. 다시 예측해 성능 하락을 측정

성능이 크게 떨어지면 그 특성에 모델이 많이 의존했을 가능성이 있습니다.

> 🙋 **매번 모델을 다시 훈련하나요?**
>
> 표준적인 permutation importance는 **재훈련하지 않습니다.**
> 고정된 모델이 그 특성 정보를 잃었을 때 얼마나 성능이 떨어지는지 봅니다.

강의에서는 개별 단어를 섞어도 큰 성능 변화가 나타나지 않았습니다.

하지만 이것이 **단어 정보가 중요하지 않다는 뜻은 아닙니다.**

- 비슷한 정보를 주는 단어가 많을 수 있음
- 다른 단어가 대체할 수 있음
- 여러 특성의 조합이 중요할 수 있음

특히 상관된 특성이 많으면 **개별 특성의 중요도가 낮게 보일 수 있습니다.**

## <span style="color:#FEB99C;">8. 진짜 시험: 다른 출처의 뉴스에도 통할까?</span>

마지막 실습은 모델을 **다른 말뭉치**에 적용하는 것이었습니다.

강의에서는 ChatGPT로 다음 기사를 생성했습니다.

- 가짜로 설정한 기사 5개: 외계인·시간 여행·뱀파이어 등
- 사실 기반으로 설정한 기사 5개: COVID·화성 탐사·기후변화 등

기존 데이터는 정치 뉴스 비중이 커 보였고,
새 데이터는 주제와 문체가 크게 달랐습니다.

### 8-1. 새 데이터에는 `fit_transform()`이 아니라 `transform()`

```python
def predict_new_articles(texts):
    cleaned = [clean_text(text) for text in texts]

    X_new = vectorizer.transform(cleaned)
    X_new = normalize(X_new).toarray().astype("float32")

    p_fake = classifier.predict(X_new, verbose=0).ravel()

    return {
        "p_fake": p_fake,
        "pred_fake": (p_fake > 0.5).astype(int)
    }
```

> ⭐ **새 데이터에서도 훈련 때의 어휘와 열 순서를 그대로 유지해야 합니다.**
> `fit_transform()`을 다시 하면 같은 열이 다른 단어를 뜻하게 될 수 있습니다.

학습 어휘에 없는 단어는 무시됩니다.
따라서 새 기사에서 중요한 단어가 기존 1,000개 어휘에 없으면,
모델은 그 정보를 제대로 활용하지 못합니다.

### 8-2. 결과: 데이터셋 내부 성능과 크게 달랐다

| 새 기사 유형 | 정답 수 |
|---|---:|
| 가짜로 설정한 기사 | 4 / 5 |
| 사실 기반으로 설정한 기사 | 2 / 5 |
| **합계** | **6 / 10** |

같은 출처에서 나눈 검증 데이터에서는 약 98%였지만,
이 작은 외부 예시에서는 **10개 중 6개**만 맞혔습니다.

다만 여기에는 중요한 주의사항이 있습니다.

> ⚠️ **이 60%를 모델의 일반적인 외부 정확도로 해석하면 안 됩니다.**
>
> 표본이 10개뿐이고, ChatGPT가 작성한 ‘사실 기반 기사’도
> 독립적인 사실 검증을 거친 정답 데이터는 아닙니다.
> 이는 정식 벤치마크보다 **분포 변화에 대한 작은 스트레스 테스트**에 가깝습니다.

그래도 교훈은 명확합니다.

### 🔎 같은 말뭉치의 홀드아웃 vs 새로운 말뭉치

| 평가 | 주로 확인하는 것 |
|---|---|
| 같은 말뭉치의 무작위 홀드아웃 | 비슷한 분포 안에서의 일반화 |
| 다른 출처·시점·주제의 데이터 | 분포 변화에 대한 일반화 |

> **“훈련에 쓰지 않았다”와 “훈련 데이터와 충분히 다르다”는 같은 말이 아닙니다.**

그리고 텍스트 분류기는 외부 근거를 찾아 사실을 검증하는 시스템과 다릅니다.

> 이 모델은 기본적으로 **“가짜로 레이블된 기사와 비슷한가?”** 를 학습합니다.
> **“현실 세계에서 이 주장이 사실인가?”** 를 직접 검증하는 것은 아닙니다.

## <span style="color:#FEB99C;">9. 중간 정리</span>

1편의 핵심을 정리하면:

- **ANN** = 가중합과 활성화 함수를 층으로 연결한 모델
- **Dense 파라미터 수** = $(입력 수+1)\times출력 수$
- **비선형성의 핵심** = 비선형 활성화 함수. 선형층만 쌓으면 결국 선형·아핀 변환
- **학습 과정** = 순전파 → 손실 → 역전파 → optimizer 업데이트
- **Epoch·Batch·Step** = 전체 반복·처리 묶음·업데이트 단위
- **Keras 흐름** = 모델 구성 → `compile()` → `fit()`
- **Early stopping** = 검증 성능이 개선되지 않으면 중단
- **최적 가중치 복원**은 별도로 설정
- **출력층과 손실함수**는 문제 유형에 맞춰 함께 선택
- **높은 정확도**일수록 누수·중복·출처·주제 단서를 점검
- **새 데이터**에는 기존 vectorizer의 `transform()` 사용
- **같은 말뭉치에서 98%**가 **다른 환경에서도 98%**를 뜻하지는 않음
