이걸 컴퓨터가 다룰 수 있게 숫자로 바꾸고, 거기서 감성·개체·유사도 같은 정보를 뽑아내는 게 이번 주차 수업의 핵심입니다.

## <span style="color:#FEB99C;">1. NLP(Nature Language Processing)이란?</span>

우리가 흔히 분석하는 데이터는 엑셀처럼 행·열로 딱 떨어지는 **정형 데이터**입니다.
반면 이미지, 음성, 그리고 **문서·이메일·뉴스·리뷰·회의록** 같은 건 그렇지 않은 **비정형 데이터**죠.

**자연어**는 "사람끼리 소통하려고 자연스럽게 발전한 언어"를 말합니다.

- Python은 자연어가 **아닙니다** → 컴퓨터에게 명령하려고 만든 언어니까요
- 수학도 자연어가 **아닙니다** → 정량 정보를 전달·변환하려는 언어니까요

결국 NLP 도구들이 하는 일은 하나로 요약됩니다.

> **자연어를 수학적 표현(숫자)으로 번역하는 것.**

이 기술은 사실 제2차 세계대전 직후 1940~50년대, "감청한 적국의 통신을 사람이 다 번역할 수 없으니 컴퓨터에게 시키자"는 **번역의 필요성**에서 출발했습니다.

NLP는 크게 3단계로 나눌 수 있습니다.

| 단계 | 하는 일 |
|---|---|
| ① 전처리(Pre-processing) | 텍스트를 분석 가능한 형태로 청소·정리 (결과 품질이 여기서 갈림) |
| ② 모델 식별(Model Training) | 분석에 쓸 "블랙박스"(감성 사전, 사전학습 분류기 등)를 정함 |
| ③ 측정·추출(Measurement) | 텍스트에서 원하는 수치 정보를 뽑아냄 |

## <span style="color:#FEB99C;">2. 토큰화: 문장을 잘게 쪼개기</span>

거의 모든 NLP는 **토큰화(Tokenization)**, 즉 텍스트를 잘게 나누는 것에서 시작합니다.
보통 문서 → 문장 → **단어(token)** 순으로 쪼갭니다.

전처리에서 자주 쓰는 용어부터 정리하겠습니다.

| 용어 | 설명 |
|---|---|
| **Token** | 텍스트를 나눈 최소 단위 (대개 단어) |
| **N-gram** | n개 단어 조합 (bigram=2개 `capital expenditure`, trigram=3개 `research and development`) |
| **Lemma(표제어)** | 같은 품사 내 단어 원형 (동사 `recording` → `record`) |
| **Stem(어간)** | 접두·접미사를 뗀 어근. **실제 단어가 아닐 수 있음** (easy/easier/easiest → `eas`) |
| **Stop words(불용어)** | 흔하고 문법상 필요하지만 의미 구분엔 기여 적은 단어 (the, is, very...) |
| **Normalization** | 문서 길이 등 스케일 효과를 제거하는 표준화 |

토큰화가 그냥 "띄어쓰기로 자르면 되는 거 아냐?"라고 생각하기 쉽지만, 그렇게 간단하지 않습니다.
`Let's tokenize, isn't this easy?` 라는 문장을 예로 들면:

| 방식 | 결과 | 문제점 |
|---|---|---|
| 공백 기준 | `tokenize` , `easy?` | 구두점이 단어에 붙어버림 ❌ |
| 공백+구두점 | `let`, `s`, `t` ... | 무의미한 조각(`s`, `t`) 발생 △ |
| **규칙 기반** | `'s`, `n't` 보존 | `n't`=not 으로 처리 가능 → 가장 실용적 ✅ |

완벽한 토큰화는 없지만, **규칙 기반 방식이 표준**이고 잘 작동합니다.

### Stemming vs. Lemmatizing

단어를 원형으로 되돌리는 두 방법이 있는데, 트레이드오프가 있습니다.

> 예: `change, changing, changes, changed` →
> - **Stemming** = `chang` (규칙 기반, 빠름, 강한 표준화. 단 실제 단어 아님)
> - **Lemmatizing** = `change` (실제 단어라 해석 유리. 단 품사 태깅 필요 → 느림)

정리하면, **실제 단어가 필요하면 lemma**, **속도·강한 표준화가 필요하면 stem**을 고릅니다.
단, stemming은 `vocal / provocative / evocative`처럼 뜻이 다른 단어를 하나(`voc`)로 합쳐버릴 위험이 있습니다.

## <span style="color:#FEB99C;">3. 문서-단어 행렬(DTM): corpus를 숫자표로</span>

여러 문서 묶음을 **코퍼스(corpus)** 라고 합니다 (뉴스·리뷰·10-K·이메일 모음 등).
이 코퍼스를 숫자표로 바꾼 게 **문서-단어 행렬(DTM, Document-Term Matrix)** 입니다.

- **행(row)** = 각 문서
- **열(column)** = 단어(token)
- **값(value)** = 보통 단어 빈도(word count)

즉 각 문서를 "단어 개수로 이루어진 벡터"로 표현하는 것이라, 이걸 **벡터 공간 표현**이라고도 합니다.
문법·어순을 무시하고 단어 빈도만 보기 때문에 **Bag-of-Words(단어 가방)** 라고 부릅니다.

| 가중치 방식 | 설명 |
|---|---|
| **Count** | 단순 단어 빈도 |
| **TF-IDF** | 단어빈도(TF) × 역문서빈도(IDF) → **희귀한 단어에 더 큰 가중치** |
| **Word Vectors** | 단어를 고차원 벡터 공간에 투영 (추후 학습) |

DTM에서 얻는 정보도 직관적입니다.

- **행 합계 = 문서 길이**
- **열 합계 = 그 단어의 인기도(빈도)**
- 대부분 값이 0인 **희소 행렬(sparse matrix)** → 메모리 효율적으로 저장 가능

> 팁: 너무 **희귀한 단어**(문서 1개에만 등장)나 너무 **흔한 단어**(모든 문서에 등장)는 유용성이 떨어집니다.
> **중간 빈도** 단어를 남기는 게 감성 분석·토픽 식별에 유리합니다.

## <span style="color:#FEB99C;">4. 감성 분석: 이 글은 긍정일까 부정일까?</span>

**감성 분석(Sentiment Analysis)** 은 텍스트의 톤(긍정/부정)을 정량화하는 기법입니다.
예를 들어 헤드폰 리뷰 3개가 있을 때 어느 게 가장 긍정적/부정적인지 숫자로 판단하는 것이죠.
접근 방식은 크게 3가지입니다.

| 접근 | 아이디어 | 장단점 |
|---|---|---|
| **사전 기반** | `good`/`bad`처럼 긍·부정 단어 사전으로 카운트 | DTM과 궁합 최고, 쉽고 유연 ↔ **문맥·수식어 무시** (`not good`을 긍정으로 오판) |
| **패턴 기반** | 사전 + 문법 보정 (`incredibly comfortable` > `comfortable`, `not`은 의미 반전) | 원문 필요 → 느림 |
| **머신러닝** | 사람의 분류를 학습해 **문맥까지** 이해 | 최신 SOTA가 항상 최고 ↔ 커스터마이징 필요 |

감성(톤) 외에도 이 기법으로 **주관성/불확실성**(신호의 강도), **독성(toxicity)**(분노 유발 여부), **금융 감성** 등을 측정할 수 있습니다.

> 재미있는 사례: `liability`(부채)는 일반 사전에선 부정 단어지만, 회계에선 그냥 방정식의 한 항일 뿐입니다.
> 그래서 *"When is a Liability a Liability?"* 라는 논문까지 나왔죠. **금융 텍스트엔 전용 사전이 필요합니다.**

### 실습: 별점으로 감성 사전 직접 만들기

리뷰 데이터엔 **별점(star rating)** 이 있으니, 이걸 활용해 나만의 사전을 만들 수 있습니다.

1. DTM을 **단어 비율(proportion)** 로 스케일링 → 리뷰 길이 효과 제거
2. 각 단어와 별점 간 **상관계수** 계산 (5,000단어 전체 상관행렬은 2,800만 개라 무거우니, 단어별로 pandas 상관만 계산 — 결측 처리에도 유리)
3. 긍정 상관 상위 25개(`love`, `great`, `easy`, `tv`) − 부정 상관 상위 25개(`returns`, `slow`)로 **커스텀 tone 지표** 생성

> ⚠️ 다만 실무에서는 **holdout(훈련/검증 분리)** 이 필수입니다.
> 같은 데이터에서 뽑은 단어가 다른 데이터에서도 통할지는 out-of-sample로 검증해야 하니까요.

패턴 기반은 **TextBlob** 패키지로 손쉽게 할 수 있는데, 문장 단위로 **polarity(극성)** 와 **subjectivity(주관성)** 를 반환합니다.

## <span style="color:#FEB99C;">5. 개체명 인식(NER): 문서에서 핵심 정보 콕 집기</span>

**NER(Named Entity Recognition)** 은 문서에서 **사람·조직·장소·제품·날짜** 같은 핵심 개체를 찾아 분류하는 기법입니다.
과정은 ① 개체 **탐지** → ② 개체 **분류** 두 단계입니다.

비즈니스 활용 예시를 들면:

- Apple이 소셜미디어에서 "iPhone" 언급 + 감성을 함께 모니터링해 **응대 우선순위** 결정
- 고객 지원 티켓 자동 분류, HR에서 이력서의 대학·조직·지역 추출 등

접근 방식은 감성 분석과 판박이입니다.

| 접근 | 특징 |
|---|---|
| **사전(Lexicon) 기반** | 정해진 개체 목록과 매칭. 신규 개체엔 약하나, 제품 목록처럼 확정된 경우엔 훌륭 |
| **규칙(Rules) 기반** | 이름·장소처럼 패턴이 정형화된 개체에 효과적 |
| **머신러닝 기반** | 주석(annotated) 텍스트로 학습. **최고 성능 NER은 대부분 ML** (정확도 90%+) |

> ⚠️ 완벽하진 않습니다. 실제 예시에서 `Macbook`이 조직(ORG)으로 오분류되기도 했죠. 그래도 매우 유용합니다.

### 실습: 뉴스 코퍼스에 NER 적용

spaCy로 뉴스 기사에 NER을 적용하고, 개체 타입별/실제 개체별 빈도를 **Counter**로 집계했습니다.
개체가 없을 땐 `N/A`로 처리해 에러를 방지하고, 결과를 DataFrame으로 변환(`fillna(0)`)했습니다.

- 최빈 개체: **Trump > Obama > Clinton**
- 최빈 개체 타입: **PERSON > ORG > ...**

> 소소한 함정: 문자열 컬럼(`most_common`)을 `sum`하면 문자열이 이어붙여져 정렬 시 **TypeError**가 납니다.
> 정렬 전에 그 컬럼을 빼주면 해결됩니다.

## <span style="color:#FEB99C;">6. 텍스트 유사도: 두 문서가 얼마나 닮았을까?</span>

두 숫자의 가까움은 쉽지만, **텍스트의 유사도**는 좀 더 복잡합니다.
DTM으로 문서를 벡터로 만들었으니, 두 벡터의 관계로 유사도를 잴 수 있습니다.

| 측정 방식 | 원리 | 특징 |
|---|---|---|
| **유클리드 거리** | 피타고라스 정리 (두 점 사이 직선 거리) | **길이(스케일)에 크게 영향받음** |
| **코사인 유사도** | 두 벡터 사이 **각도** | 0~1, **스케일 무시** |

> 비유하자면, 문서 A가 100단어·문서 B가 150단어일 때 그 "길이 차이 50단어"가 유사도를 좌우하는 걸 원하진 않습니다.
> 우리가 알고 싶은 건 **"쓰인 언어가 얼마나 비슷한가"** 니까요. 그래서 길이를 무시하는 **코사인 유사도가 텍스트의 정석**입니다.

계산도 선형대수로 간단합니다. 두 행렬의 내적을 각 노름(norm)의 곱으로 나누면 됩니다.
scikit-learn의 `cosine_similarity(dtm, dtm)` 한 줄이면 코퍼스 내 모든 문서쌍의 유사도가 나옵니다.
(대각선은 자기 자신이라 항상 1이므로 제외하고, `argsort`로 각 리뷰의 가장 닮은 리뷰를 찾습니다.)

> 🎯 응용 아이디어: 여러 리뷰와 **광범위하게** 닮은 리뷰는 "I like this product" 같은 **제네릭(generic)한 리뷰**일 가능성이 높습니다.

## <span style="color:#FEB99C;">7. 결론</span>

> NLP의 핵심은 결국 **"자연어를 숫자(벡터)로 번역한 뒤, 거기서 원하는 정보를 뽑아내는 것"** 입니다.
> 토큰화 → DTM → 감성/NER/유사도로 이어지는 파이프라인이 그 뼈대입니다.

이번 주에 배운 것을 정리하면:

- **NLP = 전처리 → 모델 식별 → 측정/추출**
- **토큰화**는 모든 NLP의 출발점, stemming↔lemmatizing은 **속도 vs 해석력** 트레이드오프
- **DTM(Bag-of-Words)** 은 코퍼스의 벡터 표현. Count / TF-IDF, 대부분 희소 행렬
- **감성 분석**: 사전 → 패턴(TextBlob) → ML로 갈수록 정교하지만 비용도 큼
- **NER**: 사람·조직·장소 등 개체 식별, 최고 성능은 ML 기반
- **문서 유사도**는 길이 영향을 없앤 **코사인 유사도**가 정석
