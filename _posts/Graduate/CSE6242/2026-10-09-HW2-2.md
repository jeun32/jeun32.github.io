지난 전반부에서는 Tableau로 표와 막대그래프를 만들고(Q1), D3.js로 보드게임 관계를 네트워크로 표현하며(Q2), Vega-Lite로 평가 수의 시간적 변화를 비교했습니다(Q3).

이번 후반부(Q4~Q5)의 중심은 **상호작용(Interaction)**이었습니다.

정적인 차트는 작성자가 선택한 정보만 보여줍니다. 반면 인터랙티브 시각화에서는 사용자가 직접 마우스를 올리고, 연도를 바꾸고, 관심 있는 대상을 탐색할 수 있습니다.

이번에는 다음 두 가지를 구현했습니다.

1. **보드게임 평점 분포의 원에 마우스를 올리면, 해당 그룹의 인기 게임 막대그래프가 나타나는 연동 차트**
2. **연도를 선택하면 국가별 사건 수와 범례가 바뀌는 야생동물 밀수 지도**

화면을 그리는 것뿐 아니라, **사용자 행동에 따라 어떤 데이터를 선택하고 무엇을 갱신할지**를 설계하는 과정이었습니다.

## <span style="color:#FEB99C;">1. Q4: 전체 분포에서 개별 게임으로 내려가기</span>

Q4의 데이터에는 게임 이름, 출시 연도, 평균 평점, 평가 참여 수가 들어 있었습니다.

```text
name, year, average_rating, users_rated
```

목표는 2015~2019년에 출시된 게임들의 평점 분포를 보여주고, 관심 있는 연도·평점 조합의 상세 게임 목록을 탐색하게 만드는 것이었습니다.

위쪽 선 그래프와 아래쪽 막대그래프는 서로 다른 질문에 답합니다.

| 차트 | 질문 | 사용하는 값 |
|---|---|---|
| **위쪽 선 그래프** | 이 연도에 이 평점 구간의 게임이 몇 개 있을까? | 게임 개수 |
| **아래쪽 막대그래프** | 그중 어떤 게임이 가장 많이 평가되었을까? | `users_rated` |

**게임 개수와 평가 참여 수를 혼동하지 않는 것**이 첫 번째 핵심이었습니다.

### ① 평점을 정수 구간으로 묶기

평점은 `7.71148`처럼 소수점으로 주어져 있었습니다.

이를 `Math.floor()`로 내림하여 정수 구간으로 묶었습니다.

```javascript
rating: Math.floor(+d.average_rating)
```

예를 들어:

```text
7.71148 → 7
6.96768 → 6
8.12219 → 8
```

평점 6 그룹은 정확히 6.0인 게임만 뜻하는 것이 아니라, **6 이상 7 미만인 게임들**을 의미합니다.

그다음 출시 연도와 내림 평점으로 데이터를 그룹화했습니다.

```javascript
const grouped = d3.nest()
  .key(function(d) {
    return d.year;
  })
  .key(function(d) {
    return d.rating;
  })
  .object(selectedData);
```

이를 개념적으로 보면 다음과 같습니다.

```text
2019년
 ├── 평점 6 → 28개
 ├── 평점 7 → 78개
 ├── 평점 8 → 52개
 └── 평점 9 → 8개
```

각 묶음의 길이를 세면 선 그래프에 사용할 게임 수가 됩니다.

### ② 데이터가 없는 구간도 0으로 채우기

어떤 연도에는 특정 평점 구간의 게임이 하나도 없었습니다.

이때 해당 점을 생략하면 선이 중간 구간을 건너뛰어 연결되어 분포를 다르게 보이게 할 수 있습니다. 따라서 모든 연도에 대해 0부터 최대 평점까지의 구간을 생성하고, 없는 조합은 0개로 채웠습니다.

```javascript
const games =
  (grouped[year] && grouped[year][rating]) || [];

const point = {
  year: year,
  rating: rating,
  count: games.length
};
```

해당 조합에 데이터가 없으면 빈 배열을 사용하므로 `games.length`는 0이 됩니다.

그 결과 각 연도에 동일한 평점 구간이 생기고, 게임이 없는 곳에도 Y=0인 점을 표시할 수 있었습니다.

### ③ 같은 선 그래프라도 시간 축은 아니다

Q3에서는 X축이 날짜였지만, Q4의 X축은 **평점 구간**입니다.

따라서 Q4의 선을 오른쪽으로 따라간다고 시간이 흐르는 것은 아닙니다. 각 연도별 게임 분포를 연결한 **도수다각형(Frequency Polygon)**에 가깝습니다.

제공 데이터에서 평점 6 구간의 게임 수는 다음과 같았습니다.

| 출시 연도 | 게임 수 |
|---|---:|
| 2015 | 524 |
| 2016 | 532 |
| 2017 | 497 |
| 2018 | 349 |
| 2019 | 28 |

여기서 2019년의 수가 작다고 해서 곧바로 "2019년에 보드게임 시장이 축소되었다"고 결론 내릴 수는 없습니다. 데이터 수집 시점과 포함 범위 등도 영향을 줄 수 있기 때문입니다.

시각화는 관찰된 분포를 보여주지만, **그 차이의 원인까지 자동으로 설명해 주지는 않습니다.**

## <span style="color:#FEB99C;">2. Q4: 마우스 이벤트로 상세 막대그래프 연결하기</span>

### ① 마우스를 올리면 해당 그룹의 상위 5개 추출

선 그래프의 원 하나에는 다음과 같은 정보가 연결되어 있습니다.

```javascript
{
  year: 2019,
  rating: 6,
  count: 28
}
```

해당 원에 마우스를 올리면 같은 연도·평점의 게임들을 찾고, 평가 참여 수 기준으로 정렬했습니다.

```javascript
const topGames = matchingGames.slice()
  .sort(function(a, b) {
    return (
      d3.descending(a.users_rated, b.users_rated) ||
      d3.ascending(a.name, b.name)
    );
  })
  .slice(0, 5);
```

처리 과정은 다음과 같습니다.

1. 원본 배열을 복사합니다.
2. `users_rated`가 큰 순서로 정렬합니다.
3. 동점이면 게임 이름으로 순서를 정합니다.
4. 앞에서 5개만 선택합니다.

게임이 5개보다 적으면 있는 만큼만 표시됩니다.

앞의 `.slice()`는 정렬하기 전에 배열을 복사하기 위한 것입니다. 원본 그룹의 순서를 의도치 않게 바꾸지 않도록 했습니다.

2019년 평점 6 그룹의 실제 상위 게임은 다음과 같았습니다.

| 게임 | 평가 참여 수 |
|---|---:|
| LAMA | 392 |
| Victorian Masterminds | 367 |
| Blood on the Clocktower | 309 |
| Unlock! Night of the Boogeymen | 204 |
| Corinth | 193 |

전체 분포의 점 하나가 **구체적인 게임 목록으로 연결되는 구조**가 완성된 것입니다.

### ② 긴 이름은 데이터가 아니라 표시 단계에서 자르기

막대그래프의 Y축에는 게임 이름의 앞 10글자만 표시하도록 했습니다.

```javascript
.tickFormat(function(name) {
  return name.slice(0, 10);
})
```

여기서 원본 게임 이름 자체를 먼저 자르면 문제가 생길 수 있습니다. 서로 다른 게임의 앞 10글자가 같을 수 있기 때문입니다.

따라서:

- 데이터와 스케일의 domain → 전체 이름
- 화면에 표시하는 축 레이블 → 앞 10글자

로 분리했습니다.

이는 **데이터의 식별값과 사용자에게 보여주는 문자열은 다르게 관리할 수 있다**는 좋은 예였습니다.

### ③ Mouseover와 Mouseout은 한 쌍

Mouseover에서는 원을 크게 하고 막대그래프를 표시했습니다.

```javascript
.on("mouseover", function(d) {
  d3.select(this).attr("r", hoverRadius);

  if (d.count === 0) {
    hideBarChart();
    return;
  }

  showBarChart(d);
})
```

게임 수가 0인 경우에도 원은 커지지만, 막대그래프는 표시하지 않습니다.

Mouseout에서는 반대로 원래 상태를 복구했습니다.

```javascript
.on("mouseout", function() {
  d3.select(this).attr("r", normalRadius);
  hideBarChart();
})
```

상호작용은 "보여주기"만 구현해서 끝나는 것이 아니었습니다. **언제 숨길지, 강조를 어떻게 되돌릴지까지 정의해야** 화면 상태가 일관되게 유지되었습니다.

또한 이벤트 처리 방식은 사용하는 D3 버전에 맞춰야 했습니다. 이번 과제는 D3 v5이므로, 다른 버전 예제의 이벤트 인자 구조를 그대로 가져오지 않도록 주의했습니다.

### ④ 디버깅 경험: 축 범위와 눈금 간격은 다르다

자동 채점에서 Y축 눈금이 부족하다는 오류가 발생했습니다.

현재 표시:

```text
0, 100, 200, 300, 400, 500
```

기대하는 표시:

```text
0, 50, 100, 150, 200, 250, 300, 350, 400, 450, 500
```

문제는 축의 상한이 아니라 `.ticks(6)` 설정이었습니다.

이를 다음처럼 수정했습니다.

```javascript
d3.axisLeft(y)
  .ticks(10)
```

현재 데이터 범위에서는 이 설정이 50 간격의 눈금을 생성합니다.

여기서 `.ticks(10)`은 정확히 10개를 강제하는 명령이 아니라, **약 10개가 되도록 읽기 좋은 간격을 선택하는 요청**입니다.

축의 domain은 계속 데이터에서 구했습니다.

```javascript
.domain([0, maxCount])
```

실제 최대 게임 수는 532였으므로, 마지막 눈금이 500이라고 해서 축 상한을 500으로 바꾸면 안 됩니다.

**축의 범위와 표시되는 눈금 목록은 별개의 설정**이라는 점을 이해할 수 있었습니다.

## <span style="color:#FEB99C;">3. Q5: 야생동물 밀수 사건을 세계 지도 위에 표현하기</span>

Q5에서는 다시 야생동물 밀수 데이터로 돌아왔습니다.

이번에는 사건 이동 경로가 아니라, **연도별 국가 단위 사건 수**를 지도 색상으로 표현했습니다.

이처럼 지역별 통계값에 따라 색을 채우는 지도를 **단계구분도(Choropleth Map)**라고 합니다.

사용한 파일은 두 개였습니다.

| 파일 | 역할 |
|---|---|
| `wildlife_trafficking.csv` | 연도·국가별 사건 수, 평균 벌금, 평균 징역 기간 |
| `world_countries.json` | 국가 경계를 담은 GeoJSON |

CSV는 "어떤 값을 보여줄지", GeoJSON은 "어디에 그릴지"를 제공하는 셈입니다.

### ① 지도도 좌표 변환부터 시작한다

지구의 경도·위도를 평면 화면에 그대로 그릴 수는 없습니다. 이를 평면 좌표로 옮기는 규칙이 **지도 투영법(Projection)**입니다.

이번에는 Natural Earth 투영을 사용했습니다.

```javascript
var projection = d3.geoNaturalEarth1();

var path = d3.geoPath()
  .projection(projection);
```

`projection`이 지리 좌표를 화면 좌표로 변환하고, `path`가 그 결과를 SVG 경로로 만듭니다.

국가 하나는 하나의 `<path>` 요소로 표현됩니다.

```javascript
countriesGroup.selectAll("path")
  .data(world.features)
  .enter()
  .append("path")
  .attr("d", path);
```

제공된 지도는 이미 GeoJSON FeatureCollection이어서 별도의 TopoJSON 변환은 필요하지 않았습니다.

### ② CSV와 지도는 국가 이름으로 연결

국가의 색상을 정하려면 지도 속 국가와 CSV의 국가를 대응시켜야 합니다.

```javascript
feature.properties.name
```

으로 GeoJSON의 국가 이름을 읽고, 같은 이름의 CSV 기록을 찾았습니다.

실제 CSV의 국가 열 이름은 `Country of Incident`였습니다. 공백이 있는 열 이름이므로 다음처럼 접근했습니다.

```javascript
d["Country of Incident"]
```

이 과정에서 중요한 것은 **문서의 예시보다 실제 파일의 열 이름과 값을 확인하는 것**이었습니다.

예를 들어 첨부 데이터에서 미국은 `USA`로 들어 있었습니다. 임의로 `United States of America`로 바꾸면 지도와 CSV의 연결이 끊어질 수 있습니다.

### ③ 연도 목록도 데이터에서 생성

드롭다운의 연도를 직접 적는 대신 CSV에서 추출했습니다.

```javascript
var years = Array.from(
  new Set(
    traffickingData.map(function(d) {
      return d.year;
    })
  )
).sort(d3.ascending);
```

처리 순서는 다음과 같습니다.

1. 각 행에서 연도 추출
2. `Set`으로 중복 제거
3. 오름차순 정렬

제공 데이터에서는 2015~2024년이 추출되었습니다.

가장 이른 연도를 기본값으로 설정하고, 선택이 바뀌면 다음 두 가지를 함께 갱신했습니다.

- 국가별 색상
- 색상 범례

지도만 바뀌고 범례가 그대로라면 사용자는 잘못된 기준으로 색을 해석하게 됩니다. **필터에 의존하는 요소들을 함께 갱신하는 것**이 중요했습니다.

## <span style="color:#FEB99C;">4. Q5: 왜 사건 수를 사분위수로 나눴을까?</span>

일부 국가의 사건 수가 매우 크면, 선형 색상 스케일에서는 나머지 국가들이 거의 같은 연한 색으로 보일 수 있습니다.

이를 완화하기 위해 **Quantile Scale**을 사용했습니다.

```javascript
var colorScale = d3.scaleQuantile()
  .range([
    "#eff3ff",
    "#bdd7e7",
    "#6baed6",
    "#2171b5"
  ]);
```

같은 파란색 계열을 연한 색부터 진한 색까지 정확히 네 단계로 나누었습니다.

### ① 값의 범위가 아니라 분포를 기준으로 나누기

Quantile scale은 정렬된 데이터의 분위수를 경계로 사용합니다.

2015년의 실제 경계는 다음과 같았습니다.

```text
최솟값: 1
25% 지점: 2
50% 지점: 4
75% 지점: 16
최댓값: 269
```

따라서 네 구간은 다음과 같습니다.

| 색상 단계 | 사건 수 범위 |
|---|---|
| 가장 연함 | [1, 2) |
| 두 번째 | [2, 4) |
| 세 번째 | [4, 16) |
| 가장 진함 | [16, 269] |

`[a, b)`는 a 이상, b 미만을 의미합니다. 마지막 구간은 최댓값도 포함합니다.

같은 값이 여러 국가에 반복되면 각 색상에 들어가는 국가 수가 정확히 같아지지는 않습니다. 사분위수는 **데이터 분포를 나누는 경계**이지, 무조건 동일한 개수의 국가를 배정하는 규칙은 아닙니다.

또한 분위수 계산에는 지도에 표시되는 국가만이 아니라, **선택한 연도의 CSV에 포함된 모든 국가**를 사용했습니다.

### ② 연도별 색상은 상대적이라는 주의점

2021년의 경계는 다음처럼 달랐습니다.

```text
1 → 2 → 7 → 25 → 578
```

따라서 가장 진한 색은:

- 2015년: 16건 이상
- 2021년: 25건 이상

을 의미합니다.

즉, 두 연도에서 같은 색이라고 해서 사건 수가 같지는 않습니다.

> **연도별 quantile 지도는 그해 국가들 사이의 상대적 위치를 비교하는 데 유용하지만, 색상만으로 연도 간 절대 수치를 비교하기에는 주의가 필요합니다.**

이 때문에 연도가 바뀔 때 범례도 반드시 갱신해야 했습니다.

색상은 숫자를 보기 쉽게 압축해 주지만, 그 과정에서 **어떤 기준으로 압축했는지**를 함께 전달해야 한다는 점을 배웠습니다.

### ③ 데이터 없음은 0이 아니다

특정 국가·연도의 기록이 없으면 회색으로 표시했습니다.

```javascript
return record
  ? colorScale(record.incidents)
  : noDataColor;
```

하지만 회색은 **밀수 사건이 전혀 없었다는 증거가 아니라, 제공 데이터에 해당 기록이 없다는 뜻**입니다.

또한 벌금이나 징역 기간만 비어 있는 경우에는 국가를 회색으로 만들지 않았습니다. 지도 색상은 사건 수를 기준으로 결정하기 때문입니다.

마찬가지로 지도에 표시된 사건 수는 데이터에 기록된 규모이지, 실제 발생한 모든 밀수 활동의 규모라고 단정할 수 없습니다.

적발과 보고 체계의 차이도 기록된 사건 수에 영향을 줄 수 있습니다.

## <span style="color:#FEB99C;">5. Q5: 작은 Tooltip에도 상태 관리가 필요하다</span>

국가에 마우스를 올리면 다음 정보를 표시했습니다.

```text
Country: USA
Year: 2021
Number of Incidents: 36
Average Fine (USD): 15150.00
Average Imprisonment (years): 51.67
```

Tooltip은 과제 요구에 따라 **d3-tip**으로 생성했습니다.

### ① 빈칸을 0으로 바꾸지 않기

CSV의 평균 벌금과 징역 기간에는 빈칸이 많았습니다.

JavaScript에서는 다음 결과가 0입니다.

```javascript
+""
```

이를 그대로 사용하면 정보가 없는 벌금을 0달러로 표현하게 됩니다.

따라서 숫자로 바꾸기 전에 빈칸인지 확인했습니다.

```javascript
function parseOptionalNumber(value) {
  if (value === undefined || value === null) {
    return null;
  }

  var text = String(value).trim();

  if (text === "") {
    return null;
  }

  var number = +text;

  return Number.isFinite(number) ? number : null;
}
```

화면에서는 다음과 같이 구분했습니다.

- 유효한 숫자 → 소수점 두 자리
- 결측값 → `N/A`

예를 들어 2015년 Angola는 사건 수가 5건이지만 평균 벌금과 징역 기간은 비어 있었습니다.

```text
Country: Angola
Year: 2015
Number of Incidents: 5
Average Fine (USD): N/A
Average Imprisonment (years): N/A
```

**결측값 처리 역시 시각화의 정확성을 결정하는 작업**이었습니다.

### ② Tooltip 깜빡임 방지

Tooltip이 마우스 이벤트를 받으면 다음 상황이 발생할 수 있습니다.

```text
국가 위로 이동
→ Tooltip 표시
→ Tooltip이 마우스를 가로챔
→ 국가에서 mouseout 발생
→ Tooltip 숨김
```

이 과정이 반복되면 Tooltip이 깜빡입니다.

이를 막기 위해 다음 설정을 적용했습니다.

```javascript
.style("pointer-events", "none")
```

Tooltip은 정보를 보여주되, 국가에 전달될 마우스 이벤트는 방해하지 않도록 한 것입니다.

### ③ Tooltip은 하나만 생성하기

국가마다 새 Tooltip을 만들지 않고, 하나의 요소를 재사용했습니다.

| 이벤트 | 처리 |
|---|---|
| `mouseover` | 내용 갱신 후 표시 |
| `mousemove` | 위치 갱신 |
| `mouseout` | 숨김 |

화면 가장자리에서는 Tooltip의 크기를 측정해 반대편으로 옮기고, 화면 밖으로 벗어나지 않도록 좌표를 제한했습니다.

작은 설명 상자 하나도 **생성, 갱신, 위치, 숨김이라는 수명주기**를 갖고 있었습니다.

## <span style="color:#FEB99C;">6. 공통 디버깅: 경로와 DOM도 구현의 일부다</span>

### ① 상대 경로는 HTML 위치를 기준으로 생각하기

페이지가 공백으로 보이거나 데이터가 나타나지 않을 때, 가장 먼저 확인해야 할 것은 라이브러리와 데이터 경로였습니다.

```text
./lib/  → 현재 HTML이 있는 폴더 안의 lib
../lib/ → 한 단계 위 폴더 안의 lib
```

Q5 데이터는 `data` 폴더 안에 있었으므로 다음 경로를 사용했습니다.

```javascript
d3.json("data/world_countries.json")
d3.csv("data/wildlife_trafficking.csv")
```

라이브러리와 데이터의 상대 경로는 각각 실제 폴더 구조에 맞춰야 합니다.

또한 HTML을 파일로 직접 열기보다 Python HTTP 서버로 실행하고, Chrome 개발자 도구에서 404 오류와 JavaScript 오류를 확인했습니다.

```bash
python -m http.server 8000
```

브라우저에 빈 화면이 나온다고 해서 무조건 차트 계산이 잘못된 것은 아니었습니다. **필요한 파일이 로드되지 않아 코드 실행 자체가 시작되지 않은 경우**부터 확인해야 했습니다.

### ② 라이브러리 로딩 순서도 중요하다

d3-tip처럼 D3에 의존하는 라이브러리는 D3 다음에 불러와야 합니다.

```html
<script src="../lib/d3.v5.min.js"></script>
<script src="../lib/d3-tip.min.js"></script>
```

또한 과제의 import 안내 테스트는 실제 코드에서 직접 사용하는 라이브러리뿐 아니라 지정된 라이브러리 참조도 확인했습니다.

해당 안내는 0점 배점의 advisory 항목이었지만, 채점 환경에서의 로딩 문제를 예방하기 위해 요구된 상대 경로와 import 목록을 확인했습니다.

### ③ 화면뿐 아니라 DOM 구조도 맞아야 한다

자동 채점기는 그림을 눈으로만 보는 것이 아니라, 특정 ID를 가진 요소를 찾아 검사합니다.

예를 들어 Q5는 다음 구조를 요구했습니다.

```html
<select id="yearDropdown"></select>

<svg id="choropleth">
  <g id="countries"></g>
  <g id="legend"></g>
</svg>

<div id="tooltip"></div>
```

이것은 렌더링 후의 구조입니다. 실제 Tooltip 요소는 d3-tip이 생성하도록 했으며, HTML에서 같은 ID의 div를 추가하지 않았습니다.

개발자 도구에서 개수를 확인하면 중복 생성이나 누락을 찾기 쉽습니다.

```javascript
document.querySelectorAll("#legend rect").length
// 기대: 4

document.querySelectorAll("#tooltip").length
// 기대: 1
```

시각화도 결국 웹 애플리케이션이므로, **보이는 결과뿐 아니라 요소 구조와 상태가 안정적이어야 한다**는 점을 배웠습니다.
