## <span style="color:#FEB99C;">2. Q1: 비행기 길을 선으로 잇다 (네트워크 & 중심성 분석)</span>

Q1의 목표는 전 세계 항공 노선도 위에 밀수꾼들의 이동 경로를 올려서 **"밀수 항공 네트워크 지도"**를 만드는 것이었습니다.

외부 패키지(`networkx` 등)를 쓰지 않고, 순수 파이썬 기본 문법만으로 그래프(Graph) 알고리즘을 직접 바닥부터 구현했습니다.

### ① 그래프의 기본: 점(Node)과 선(Edge)
컴퓨터 과학에서 말하는 **그래프(Graph)**는 막대그래프가 아니라, **지하철 노선도처럼 점들을 선으로 이어놓은 그물망**을 뜻합니다.

- **점(Node)**: 전 세계 공항 (예: `ICN` 인천, `JFK` 뉴욕, `BKK` 방콕)
- **선(Edge)**: 공항 사이를 오가는 비행기 노선 (인천 ↔ 뉴욕)
- **무방향(Undirected)**: 비행기가 오고 가기 때문에 `(A, B)`와 `(B, A)`는 완전히 똑같은 노선 1개로 취급합니다.

### ② "누가 제일 마당발인가?" 연결 중심성 (Degree Centrality)
각 공항이 네트워크 안에서 얼마나 중요한지 숫자로 점수를 매기는 방법이 바로 **연결 중심성(Degree Centrality)**입니다.

$$Degree\ Centrality(v) = \frac{d(v)}{N - 1}$$

- $$d(v)$$: 그 공항에 연결된 비행기 노선 개수
- $$N$$: 네트워크에 등록된 전체 공항 개수 ($$N-1$$은 나를 뺀 다른 모든 공항 수)

즉, "이론상 연결될 수 있는 최대 노선 수 중에서 실제로 몇 개의 노선이 연결되어 있는가?"를 0과 1 사이의 비율로 계산하는 공식입니다.

```python
# 노선이 0개인 외딴 공항도 점수에 포함하고, 소수점 6자리로 반올림
denom = N - 1 if N > 1 else 1
for node, d in degrees.items():
    score = 0.0 if N <= 1 else d / denom
    centrality[node] = round(score, 6)
```

### ③ 분석 결과가 말해주는 사실
전체 비행 네트워크(`full_graph`)와 밀수 사건 비행 네트워크(`iwt_graph`)의 중심성 순위표를 나란히 뽑아 비교해 보았습니다.

- **일반 비행 네트워크 상위권**: 애틀랜타(`ATL`), 런던 히드로(`LHR`)처럼 평소 환승객과 노선이 많은 대형 공항들
- **밀수 비행 네트워크 상위권**: **방콕(`BKK`), 홍콩(`HKG`), 두바이(`DXB`), 요하네스버그(`JNB`)** 같은 공항들이 상위권으로 진입!

야생동물의 주요 서식지(아프리카, 동남아)에서 출발해 최종 소비지(동아시아 등)로 갈 때 거치는 **환승 거점 공항들의 위치**를 데이터로 확인할 수 있었습니다.

## <span style="color:#FEB99C;">3. Q2: 수사 일지 파헤치기 (SQLite 데이터베이스)</span>

Q2에서는 단속 일지 엑셀(CSV) 파일 3개를 경량 데이터베이스인 **SQLite**에 집어넣고, SQL 쿼리를 날려 필요한 통계를 뽑아냈습니다.

### ① 테이블 설계와 빠른 검색을 위한 인덱스(Index)
사건 기록을 세 개의 테이블로 나누어 저장했습니다.
- `incidents`: 사건 기본 정보 (사건 ID, 사건 유형, 날짜)
- `details`: 현장 세부 정보 (밀수 품목, 이동 수단, 적발 단속법)
- `outcomes`: 법원 판결 결과 (벌금, 징역 기간, 체포 인원)

사건 번호(`report_id`)에 **인덱스(Index, 색인 목차)**를 걸어두어, 데이터 양이 많아져도 원하는 사건을 빠르게 조회할 수 있도록 구성했습니다.

```sql
CREATE INDEX incident_index ON incidents(report_id);
```

### ② 단위 통일: "징역을 가장 길게 선고받은 밀수 범죄는?"
판결문 데이터를 보면 어떤 사건은 `2 years`, 어떤 건 `6 months`, 어떤 건 `30 days`처럼 기간 단위가 제각각이었습니다.

SQL의 `CASE WHEN` 문을 써서 모든 징역 기간을 **'일(Day)' 단위로 환산(1년=365일, 1달=30일, 1주일=7일)**한 뒤 평균을 냈습니다.

```sql
ROUND(AVG(
    CASE 
        WHEN LOWER(o.prison_time_unit) LIKE '%year%' THEN COALESCE(o.prison_time, 0) * 365
        WHEN LOWER(o.prison_time_unit) LIKE '%month%' THEN COALESCE(o.prison_time, 0) * 30
        WHEN LOWER(o.prison_time_unit) LIKE '%week%' THEN COALESCE(o.prison_time, 0) * 7
        WHEN LOWER(o.prison_time_unit) LIKE '%day%' THEN COALESCE(o.prison_time, 0)
        ELSE 0
    END
), 2) AS avg_prison_time_days
```

이를 통해 단순 개인 소지 사건보다 대규모 조직 밀수 적발(`Seizure`) 사건에 법원이 훨씬 무거운 실형을 내렸다는 점을 수치로 확인할 수 있었습니다.

### ③ 문맥 기반 단어 검색: FTS5 (Full Text Search)
유용했던 기능 중 하나는 가상 테이블을 활용한 **전문 검색(FTS5)**이었습니다.

밀수 피해가 극심한 **천산갑(Pangolin)** 관련 사건 중, 내용 안에 **'dead(죽은)'**와 **'pangolin'** 두 단어가 **사이에 다른 단어가 2개 이하로 인접해 있는 사건**만 짚어내는 쿼리입니다.

```sql
SELECT COUNT(*)
FROM incident_overviews
WHERE subject MATCH 'NEAR(dead pangolin, 2)';
```
- `"1 dead Sunda pangolin"` $$\rightarrow$$ 중간에 단어 1개(`Sunda`)이므로 검색 성공
- `"1 live pangolin seized and 2 dead birds found"` $$\rightarrow$$ 두 단어 사이가 멀어 제외

단순한 키워드 포함 여부를 넘어, 단어 간의 거리까지 고려해 정확한 사건 기록을 추려낼 수 있었습니다.
